# Ruflo

**面向 Claude Code 的多智能体（Agent）AI 编排工具**

</div>

在机器、团队和信任边界之间编排 100+ 专业 AI Agent。Ruflo 为 Claude Code 添加了协同蜂群（Swarm）、自学习记忆、联邦通信和企业级安全功能——让 Agent 不再只是独立运行，而是真正协作。

### 为什么选择 Ruflo？

> Claude Flow 现已更名为 Ruflo——由 [`rUv`](https://ruv.io) 命名，他热爱 Rust、心流状态，以及打造那些“理所当然就该存在”的产品。“Ru”取自 rUv，“flo”代表熬夜到凌晨三点。底层基于 [`Cognitum.One`](https://cognitum.one/?RuFlo) 的 Agent 架构运行，搭载强化版 Rust AI 引擎、Embedding 模型、记忆系统和插件生态。


### Ruflo 能做什么

只需执行一次 `npx ruvflo init`，Claude Code 就拥有了“神经系统”：Agent 自动组织成蜂群协作，从每项任务中学习，跨会话保持记忆，并通过联邦通信在其他机器上的 Agent 之间安全交流而不泄露数据。你继续写代码，Ruflo 负责协调工作。

```
Self-Learning / Self-Optimizing Agent Architecture

User --> Ruflo (CLI/MCP) --> Router --> Swarm --> Agents --> Memory --> LLM Providers
                          ^                           |
                          +---- Learning Loop <-------+
```

> **Ruflo 新手须知？** 你无需学习 314 个 MCP 工具或 26 条 CLI 命令。完成 `init` 后，像平常一样使用 Claude Code 即可——Hook（钩子）系统会在后台自动路由任务、从成功模式中学习并协调 Agent。

## 快速开始

项目提供**两种不同的安装路径**，覆盖范围差异较大。请根据你的实际需求选择 (#1744)：

| | **Claude Code 插件** | **CLI 安装（`npx ruflo init`）** |
|---|---|---|
| 提供内容 | 斜杠命令 + 少量技能 + 每个插件对应的 Agent 定义 | 完整 Ruflo 循环 —— 98 个 Agent、60+ 条命令、30 项技能、MCP 服务器、Hooks 和守护进程 |
| 工作区文件 | **零** | `.claude/`、`.claude-flow/`、`CLAUDE.md`、辅助脚本、配置文件 |
| MCP 服务器注册 | **否**（Claude 无法调用 `memory_store`、`swarm_init` 等） | 是 |
| Hooks 安装 | 否 | 是 |
| 适用场景 | 仅试用单个插件的命令，不想进行完整安装 | 生产环境使用 —— 所有功能均按文档说明正常工作 |

### 路径 A — Claude Code 插件（轻量版，仅斜杠命令）

```bash
# 添加市场源
/plugin marketplace add ruvnet/ruflo

# 安装核心及所需插件
/plugin install ruflo-core@ruflo
/plugin install ruflo-swarm@ruflo
/plugin install ruflo-autopilot@ruflo
/plugin install ruflo-federation@ruflo
```

此方式仅添加斜杠命令和 Agent 定义。Ruflo 的 MCP 服务器**未注册**，因此 Claude 无法调用 `memory_store`、`swarm_init`、`agent_spawn` 等接口。如需完整功能，请使用下方的路径 B。

### CLI 安装

```bash
# 一键安装
curl -fsSL https://cdn.jsdelivr.net/gh/ruvnet/ruflo@main/scripts/install.sh | bash

# 或通过 npx（交互式引导）
npx ruflo@latest init wizard

# 快速非交互初始化
# npx ruflo@latest init

# 或全局安装
npm install -g ruflo@latest
```

### MCP 服务器

```bash
# 将 Ruflo 添加为 Claude Code 的 MCP 服务器（标准格式，与 USERGUIDE.md 一致）
claude mcp add ruflo -- npx ruflo@latest mcp start
```

### Web UI（测试版）—— 支持自托管，在线演示位于 [flo.ruv.io](https://flo.ruv.io/)

| 🚀 | **零门槛试用** | 打开在线链接，选择模型，输入问题。这就是完整的上手流程。 |

### 目标规划器 UI —— 自主 Agent 位于 [goal.ruv.io](https://goal.ruv.io/)

**将高层目标转化为可执行的 Agent 计划。** `goal.ruv.io` 是 RuFlo 托管的 Goal-Oriented Action Planning (GOAP) 前端——用自然语言描述期望结果，观看 RuFlo 将其拆解为前置条件、动作序列与状态空间中的 A* 路径，随后将任务分发至 [`/agents`](https://goal.ruv.io/agents) 上的实时 Agent。

| | 功能说明 | 核心价值 |
|---|------------|----------------|
| 🎯 | **自然语言目标** | 输入 *"完成认证重构并提交带测试的 PR"* —— RuFlo 自动提取成功标准、约束条件与隐含前置条件。无需 JSON，无需 DSL。 |
| 🧭 | **GOAP A* 规划器** | 将经典游戏 AI 规划移植至软件工程：通过状态空间搜索（含前置条件/效果）寻找最短可行路径。状态变化时动态重规划。 |
| 🤖 | **实时 Agent 看板** | [goal.ruv.io/agents](https://goal.ruv.io/agents) 展示所有派生 Agent —— 角色、当前步骤、记忆命名空间、Token 预算与状态。点击可检查轨迹、终止失控工作器或重新分配任务。 |

### Agent 联邦通信 —— Agent 的 Slack

```
Your Agent --> [ Remove secrets ] --> [ Sign message ] --> [ Encrypted channel ]
                 Emails, SSNs,        Proves it came       No one reads it
                 keys stripped         from you              in transit
                                                                |
                                                                v
Their Agent <-- [ Block attacks ] <-- [ Check identity ] <------+
                 Stops prompt          Rejects forgeries
                 injection

                          Audit trail on both sides.
                  Trust builds over time. Bad behavior = instant downgrade.
```

Slack 为团队提供了频道。联邦通信则为 Agent 提供了相同的能力——**跨越信任边界的共享工作区**。不同机器、组织或云区域的 Agent 可以互相发现、验证身份并协作完成任务。

核心差异在于：部分频道受信任，部分则不然。[`@claude-flow/plugin-agent-federation`](https://github.com/ruvnet/ruflo/issues/1669) 会自动处理这些逻辑。你的 Agent 加入联邦后，通过 mTLS + ed25519 验证身份并开始交换任务——离开节点前自动剥离 PII（个人身份信息），且每条消息均可审计。不受信任的 Agent 仍可参与低权限协作：它们只能看到发现信息，无法访问你的记忆数据。随着可靠性提升，信任等级会自动升级；一旦行为异常，立即降级 —— 全程无需人工介入。

你无需配置握手协议或管理证书。只需执行 `federation init`、`federation join`，Agent 即可自动通信。协议层处理身份验证，PII 管道保障数据安全，审计链路满足合规要求。

> **📘 完整用户指南：** [`docs/federation/`](./docs/federation/) —— 包含配置流程、MCP 工具说明、信任等级机制、熔断器设计，以及（可选配）将网络层可达性与联邦信任绑定的 WireGuard 网状层。架构深度解析见 ADR-111：[`docs/federation/phase7-mesh-bringup.md`](./docs/federation/phase7-mesh-bringup.md)。

<details>
<summary><strong>联邦通信能力</strong></summary>

| | 功能特性 | 实现原理 |
|---|---|---|
| 🔒 | **零信任联邦** | 远程 Agent 初始状态为不受信任。通过 mTLS + ed25519 挑战-响应机制验证身份。无需 API Key，无共享密钥。 |
| 🛡️ | **PII 过滤数据流** | 14 类检测管道扫描每条出站消息。按信任等级执行策略：BLOCK（拦截）、REDACT（脱敏）、HASH（哈希）或 PASS（放行）。自适应校准降低误报率。 |
| 📊 | **行为信任评分** | 公式（`0.4×成功率 + 0.2×在线时长 + 0.2×威胁指数 + 0.2×完整性`）持续评估对等节点。升级需历史积累，降级即时生效。 |
| 📋 | **内置合规支持** | HIPAA、SOC2、GDPR 审计轨迹作为合规模式。每次联邦事件生成结构化记录，可通过 HNSW 检索。 |
| 🤝 | **9 个 MCP 工具 + 10 条 CLI 命令** | 完整生命周期管理：`federation_init`、`federation_send`、`federation_trust`、`federation_audit` 等。 |

</details>

<summary><strong>示例：两个团队在不共享客户数据的前提下交换欺诈信号</strong></summary>

```bash
# Team A: 初始化联邦并生成密钥对
npx claude-flow@latest federation init

# Team A: 加入 Team B 的联邦端点
npx claude-flow@latest federation join wss://team-b.example.com:8443

# Team A: 发送任务 —— PII 数据在离开前自动剥离
npx claude-flow@latest federation send --to team-b --type task-request \
  --message "Analyze transaction patterns for account anomalies"

# Team A: 检查对等节点信任等级与会话健康度
npx claude-flow@latest federation status
```
