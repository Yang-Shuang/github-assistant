## 🆕 v1.3.0 新增功能

- **🌐 Web 管理界面（推荐）** — 内置于二进制文件中的完整管理面板——**无需额外依赖**。创建和编辑项目、管理提供商、监控会话、编辑定时任务，并支持**直接在浏览器中与你的 Agent 聊天**。支持 5 种语言（en/zh/zh-TW/ja/es）。我们建议你通过 Web UI 管理 cc-connect，而非手动编辑 `config.toml`。运行 `cc-connect web` 进行配置并打开仪表盘，然后运行 `cc-connect` 启动服务。
- **生命周期事件钩子** — 新增 `[[hooks]]` 配置，可在消息、会话、定时任务、权限及错误事件触发时执行 Shell 命令或 HTTP Webhook。默认异步执行，失败不阻断（fail-open）。
- **技能管理** — 新增 `/skills` 页面，内置本地技能浏览器与推荐预设。
- **全局提供商管理** — 在 Web UI 中增删改查提供商；支持从 cc-switch 配置导入。
- **个人微信** — 通过 ilink 长轮询协议使用**微信（个人号）**与你本地的 Agent 聊天；扫码 `weixin setup`，CDN 媒体传输，无需公网 IP。*[设置指南 → `docs/weixin.md`](docs/weixin.md)*
- **微博私信** — 通过 WebSocket 使用**微博私信**与你的 Agent 聊天；无需公网 IP，支持文本流式输出。
- **飞书增强功能** — 自动解析 `@name` 提及、多级回复链识别、Done 表情回应。
- **新增 Agent** — 新增 Kimi CLI 和 Pi agent 支持。

> 各平台详细设置：见下方 [📖 平台设置指南](#-platform-setup-guides)。

### 🤖 通过 AI Agent 安装与配置（推荐）

> **最简单的方式** — 将此指令发送给 Claude Code 或任何 AI 编码 Agent，它将为你处理整个安装和配置过程：

```bash
Follow https://raw.githubusercontent.com/chenhg5/cc-connect/refs/heads/main/INSTALL.md to install and configure cc-connect.
```


### 📦 手动安装

**通过 npm：**

```bash
npm install -g cc-connect
```

**通过 Homebrew（macOS / Linux）：**

```bash
brew install cc-connect
```

**从 [GitHub Releases](https://github.com/chenhg5/cc-connect/releases) 下载二进制文件：**

```bash
# Linux amd64 - Stable
curl -L -o cc-connect https://github.com/chenhg5/cc-connect/releases/latest/download/cc-connect-linux-amd64
chmod +x cc-connect
sudo mv cc-connect /usr/local/bin/

```

**从源码构建（需要 Go 1.22+）：**

```bash
git clone https://github.com/chenhg5/cc-connect.git
cd cc-connect
make build
```


### ⚙️ 配置

> **💡 提示：使用 Web UI 进行配置** — 安装完成后，运行 `cc-connect web` 打开 Web 管理面板。你可以可视化地创建项目、添加平台、管理提供商并与 Agent 聊天——无需手动编辑 TOML 文件。**注意：** `cc-connect web` 仅用于配置和打开浏览器，你仍需单独运行 `cc-connect` 来启动服务。

如果你偏好手动配置：

```bash
mkdir -p ~/.cc-connect
cp config.example.toml ~/.cc-connect/config.toml
vim ~/.cc-connect/config.toml
```

在项目中设置 `admin_from = "alice,bob"`，允许这些用户 ID 执行 `/dir` 和 `/shell` 等特权命令。
当用户运行 `/dir reset` 时，cc-connect 会恢复配置的 `work_dir` 并清除存储在 `data_dir/projects/<project>.state.json` 下的持久化覆盖配置。


### ▶️ 运行

```bash
./cc-connect
```

```bash
brew upgrade cc-connect

```

## 🎯 核心功能

### 💬 会话管理

```
/new [name]       Start a new session
/list             List all sessions
/switch <id>      Switch session
/current          Show current session
/dir [path|reset] Show, switch, or reset work directory
```

项目配置会在长时间不活跃后自动切换到新会话。这可以防止“上下文漂移”——即陈旧的历史记录（失败的命令、调试噪音）通过 `--continue` 反复被重新注入，并开始主导模型的注意力。之前的会话会被保留，并可通过 `/list` 和 `/switch` 访问。

```toml
[[projects]]
reset_on_idle_mins = 30   # default when unset; set to 0 to disable
```

未设置时默认为 **30 分钟**。设置 `reset_on_idle_mins = 0` 可禁用此功能，始终继续上一次会话。

### 🛡️ OS-用户隔离 (`run_as_user`)

在 Linux/macOS 上，项目可以以不同的 Unix 用户身份启动其 Agent，从而实现与运行 cc-connect 的 supervisor 用户的操作系统级文件系统隔离。目前由 Claude Code 支持。

```toml
[[projects]]
name = "claude-sandboxed"
run_as_user = "partseeker-coder"
run_as_env = ["PGSSLROOTCERT"]
```

目标用户需要来自 supervisor 的免密 sudo 权限（自身无需 sudo），对 `work_dir` 拥有读写权限，并拥有自己的 `~/.claude/settings.json`（包含 Agent 所需的凭据）。如果你通过 `claude.ai` OAuth 认证，请将目标用户的 `~/.claude/.credentials.json` 软链接到 supervisor 的副本中，以保持 Token 刷新同步——详见[环境传播清单](./docs/usage.md#environment-propagation-what-moves-into-the-target-users-home)。完整设置请参见
[`docs/usage.md`](./docs/usage.md#running-agents-as-a-different-unix-user-run_as_user)。

在启动 cc-connect 之前，请使用以下命令审计配置：

```bash
cc-connect doctor user-isolation
```

该命令会运行三项前置检查及隔离探针，报告目标用户可读取和不可读取的内容。如果任何检查失败或探针检测到跨用户泄露，cc-connect 将拒绝启动。

### 📎 Agent 附件回传

当 Agent 生成本地截图、图表、PDF、构建包或其他文件时，它可以将该附件发送回当前聊天窗口。

首发支持：
- Feishu
- Telegram

如果你的 Agent 未原生注入系统提示词，请在升级后于聊天中执行一次以下命令：

```text
/bind setup
```

或：

```text
/cron setup
```

这将刷新项目记忆文件中的 cc-connect 指令，使 Agent 知道如何回传附件。

你可以在 `config.toml` 中全局控制此功能：

```toml
attachment_send = "on"  # default: "on"; set to "off" to block image/file send-back
```

该开关独立于 Agent 的 `/mode`。它仅控制 `cc-connect send --image/--file`。

示例：

```bash
cc-connect send --image /absolute/path/to/chart.png
cc-connect send --file /absolute/path/to/report.pdf
cc-connect send --file /absolute/path/to/report.pdf --image /absolute/path/to/chart.png
```

注意事项：
- 绝对路径是最安全的选项。
- `--image` 和 `--file` 可重复使用。
- `attachment_send = "off"` 仅禁用附件回传；普通文本回复仍正常工作。
- 此命令用于生成的附件，不适用于普通文本回复。
