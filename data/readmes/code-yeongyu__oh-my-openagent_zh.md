# Oh My OpenAgent

你正在同时使用 Claude Code、Codex 和各种开源模型。配置工作流、调试智能体……

这些繁琐的活我们替你干了。测试了一切，只保留真正能交付成果的部分。

安装 oh-my-openagent。输入 `ultrawork`。搞定。


## 安装指南

oh-my-openagent 提供同一产品的两个版本：

- **终极版（OpenCode 专用 omo）** — 完整功能。11 个智能体、54+ 生命周期钩子、5 个内置 MCP、全部斜杠命令、团队模式、ulw-loop、ultrawork、hashline 编辑等——一应俱全。
- **轻量版（Codex CLI 专用 omo）** — 适配 Codex 插件系统的便携组件：`rules`、`comment-checker`、`lsp`、`ultrawork`、`ulw-loop`、`start-work-continuation` 和 `telemetry`。不包含智能体编排逻辑，无 `team_*` 工具，除 LSP 外无内置 MCP（这些由 Codex CLI 自身处理）。

选择你想要的版本即可。

### TL;DR

| 你的需求 | 运行命令 | 磁盘生成内容 |
| :--- | :--- | :--- |
| **终极版** (OpenCode) | `bunx oh-my-openagent install` (TUI 会引导你完成) | 在 `opencode.json` 中注册插件 + 智能体/模型配置 + 各服务商认证提示 |
| **轻量版** (Codex CLI) | `npx lazycodex-ai install` | `~/.codex/plugins/cache/sisyphuslabs/omo/` + 本地 Codex 市场缓存 + `~/.codex/config.toml` 中的市场/插件/智能体块 + 可选的自主权限 + `~/.local/bin` 中的组件 CLI |
| **两者都要** | `bunx oh-my-openagent install --platform=both` | 上述两者的组合 |

`lazycodex-ai` 默认运行 Codex 轻量版安装程序，基于 Node/npm。共享的 `omo` CLI 上的 `--platform` 参数仍默认为 `opencode`（终极版）。

### 面向人类用户

**强烈建议：让 LLM 智能体帮你完成安装。** 终极版的设置涉及订阅检测、跨 11 个智能体的模型选择以及各服务商的认证——人工操作容易出错。LLM 智能体能完整阅读指南并正确引导每一步。

将此提示词粘贴到 Claude Code、AmpCode、Cursor 或任何智能体中：

```
Install and configure oh-my-openagent by following the instructions here:
https://raw.githubusercontent.com/code-yeongyu/oh-my-openagent/refs/heads/dev/docs/guide/installation.md
```

如果你只需要**轻量版**（Codex CLI），安装程序会询问是否将 Codex 配置为自主全权限模式。你可以自己在终端一行命令完成：

```bash
npx lazycodex-ai install
# 非交互式推荐模式：
npx lazycodex-ai install --no-tui --codex-autonomous
```

对于轻量版，无需安装 Bun。在 Node/npm 环境中使用 `npx lazycodex-ai install` 即可。官方不支持全局安装；安装程序会将 Codex 插件写入 `~/.codex/`。

### 关于包名和命令名的说明

发布的 npm 包和 CLI 二进制文件仍命名为 `oh-my-opencode`（在重命名过渡期间作为 `oh-my-openagent` 双发布）。在 `opencode.json` 中，兼容层优先使用插件条目 `oh-my-openagent`，而遗留的 `oh-my-opencode` 条目仍可加载但会显示警告。插件配置文件通常仍使用 `oh-my-opencode.json[c]`；系统同时识别旧版和重命名后的基础文件名。

推荐的 `bunx`/`npx` 调用方式为 `oh-my-openagent install`（或原始的 `oh-my-opencode install`）。该包还附带了 `omo` 作为 bin 别名，但**请勿**使用 `bunx omo` 或 `npx omo` —— `omo` 是另一位作者发布的不同且无关的 npm 包，包管理器可能会解析到错误的版本。`lazycodex-ai` 是一个单用途 Node/npm 安装程序包：`npx lazycodex-ai install` 会直接路由至 Codex 轻量版安装器。它不是 Codex 市场名称（市场仓库为 `code-yeongyu/lazycodex`）。Codex 看到的是市场 `sisyphuslabs` 和插件 `omo`，启用方式为 `omo@sisyphuslabs`。

### 遥测 (Telemetry)

默认开启匿名遥测以跟踪活跃安装量（DAU/WAU/MAU）。对于两个版本，每个 UTC 日每台机器**最多发送一次**事件，使用 SHA256 哈希的安装标识符（绝不传输原始主机名），且不会创建 PostHog 用户画像。主插件会发出 `oh_my_openagent_daily_active`；Codex CLI 轻量版会从两个来源（`install_completed` 和 `session_start`）发出 `omo_codex_daily_active`。

按产品退出遥测：

- 主插件：`OMO_DISABLE_POSTHOG=1` 或 `OMO_SEND_ANONYMOUS_TELEMETRY=0`
- Codex CLI 轻量版：`OMO_CODEX_DISABLE_POSTHOG=1` 或 `OMO_CODEX_SEND_ANONYMOUS_TELEMETRY=0`（全局标志也会禁用 Codex）

详见 [隐私政策](docs/legal/privacy-policy.md) 和 [服务条款](docs/legal/terms-of-service.md)。

### 自律智能体 (Discipline Agents)

<table><tr>

**Sisyphus** (`claude-opus-4-7` / **`kimi-k2.6`** / **`glm-5.1`** ) 是你的主编排器。它负责规划、委派给专家，并以激进的并行执行推动任务完成。它不会半途而废。

**Hephaestus** (`gpt-5.5`) 是你的自主深度工作者。给它一个目标，而不是食谱。它会探索代码库、研究模式并端到端执行，无需手把手指导。*合法工匠。*

**Prometheus** (`claude-opus-4-7` / **`kimi-k2.6`** / **`glm-5.1`** ) 是你的战略规划师。访谈模式：它会提问、界定范围，并在触碰任何代码前构建详细计划。

每个智能体都针对其对应模型的优势进行了调优。无需手动切换模型。[了解更多 →](docs/guide/overview.md)

### 团队模式 (v4.0)

一个智能体很快。一支协调一致的团队则*极具破坏力*。

**团队模式**将 oh-my-openagent 从“带子智能体的单个智能体”转变为真正的多智能体系统。领队智能体编排一个按类别划分的成员团队，所有成员均**并行运行**并通过专用工具（`team_create`, `team_send_message`, `team_task_create`, `team_status`, ...）通信。在 tmux 布局中通过焦点+网格窗口实时观看每个成员的工作状态。

```jsonc
// .opencode/oh-my-openagent.jsonc
{
  "team_mode": {
    "enabled": true,
    "max_parallel_members": 4,
    "tmux_visualization": true
  }
}
```

重启 opencode 后，`team_*` 工具族将解锁。已有两个技能在此基础上运行：

- **`hyperplan`** — 5 位敌对智能体在写下一行代码前从正交角度拆解你的计划。
- **`security-research`** — 3 名漏洞猎手 + 2 名 PoC 工程师并行审计你的代码库，严重程度由*实际可利用性*校准。

> **默认关闭。需要时再启用。** [完整团队模式指南 →](docs/guide/team-mode.md)

### 智能体编排 (Agent Orchestration)

当 Sisyphus 委派给子智能体时，它不选择模型，而是选择一个**类别**。该类别会自动映射到正确的模型：

| 类别             | 用途                      |
| :------------------- | :--------------------------------- |
| `visual-engineering` | 前端、UI/UX、设计            |
| `deep`               | 自主研究 + 执行    |
| `quick`              | 单文件修改、拼写错误         |
| `ultrabrain`         | 复杂逻辑、架构决策 |

智能体会说明它需要什么类型的工作；编排框架会选择合适的模型。`ultrabrain` 现在默认路由到 GPT-5.5 xhigh。你无需触碰任何配置。

### 编码更优。哈希锚点编辑 (Hash-Anchored Edits)

编排框架问题（The Harness Problem）是真实存在的。大多数智能体失败并非模型之过，而是编辑工具的问题。

> *“这些工具都没有给模型提供一个稳定的、可验证的标识符来指向它想要修改的行……它们都依赖模型重现它已经看到的内容。当它无法做到时——而它经常做不到——用户就会责怪模型。”*
>
> <br/>- [Can Bölük, The Harness Problem](https://blog.can.ac/2026/02/12/the-harness-problem/)

受 [oh-my-pi](https://github.com/can1357/oh-my-pi) 启发，我们构建了 **Hashline**。智能体读取的每一行都会附带内容哈希标签：

```
11#VK| function hello() {
22#XJ|   return "world";
33#MB| }
```

智能体通过引用这些标签进行编辑。如果文件自上次读取后已更改，哈希将不匹配，任何损坏发生前编辑都会被拒绝。无需重现空白字符。无过期行错误。

Grok Code Fast 1：**6.7% → 68.3%** 成功率，仅因更换了编辑工具。

## 卸载指南

要移除 oh-my-openagent：

1. **从你的 OpenCode 配置中移除插件**

   编辑 `~/.config/opencode/opencode.json`（或 `opencode.jsonc`）并从 `plugin` 数组中删除 `"oh-my-openagent"` 或遗留的 `"oh-my-opencode"` 条目：

   ```bash
   # 使用 jq
   jq '.plugin = [.plugin[] | select(. != "oh-my-openagent" and . != "oh-my-opencode")]' \
       ~/.config/opencode/opencode.json > /tmp/oc.json && \
       mv /tmp/oc.json ~/.config/opencode/opencode.json
   ```

2. **移除配置文件（可选）**

   ```bash
   # 移除兼容窗口期间识别的插件配置文件
   rm -f ~/.config/opencode/oh-my-openagent.jsonc ~/.config/opencode/oh-my-openagent.json \
         ~/.config/opencode/oh-my-opencode.jsonc ~/.config/opencode/oh-my-opencode.json

   # 移除项目配置（如果存在）
   rm -f .opencode/oh-my-openagent.jsonc .opencode/oh-my-openagent.json \
         .opencode/oh-my-opencode.jsonc .opencode/oh-my-opencode.json
   ```

3. **验证移除**

   ```bash
   opencode --version
   # 插件应不再加载
   ```

4. **移除 omo-codex (Codex CLI 轻量版)**

   ```bash
   npx lazycodex-ai cleanup
   # 或者，从共享 CLI：
   omo cleanup --platform=codex
   ```

   清理命令会移除受管理的 `sisyphuslabs` Codex 缓存/市场状态，在写入备份后剥离 `~/.codex/config.toml` 中的 `omo@sisyphuslabs` 插件和 hook-state 块，并删除安装清单中列出的智能体 TOML 链接。如果特定项目仍有旧的 `oh-my-codex` / `omx` 状态，请从该项目目录运行命令或传递 `--project <path>`；它会修复已知的 `.codex/config.toml` 冲突并报告 `.codex` / `.omx` 残留文件，但不会删除项目拥有的文件。

## 功能特性

你会觉得“这本来就该有”的功能。一旦用过，就再也回不去了。

详见完整 [功能文档](docs/reference/features.md)。

**快速概览：**
- **智能体**: Sisyphus（主智能体）、Prometheus（规划器）、Oracle（架构/调试）、Librarian（文档/代码搜索）、Explore（快速代码库 grep）、Multimodal Looker
- **后台智能体**: 像真正的开发团队一样并行运行多个智能体
- **LSP & AST 工具**: 重构、重命名、诊断、AST 感知代码搜索
- **哈希锚点编辑工具**: `LINE#ID` 引用在应用每次变更前验证内容。精准编辑，零过期行错误
- **上下文注入**: 自动注入 AGENTS.md、README.md、条件规则
- **Claude Code 兼容性**: 完整的钩子系统、命令、技能、智能体、MCP
- **内置 MCP**: websearch (Exa)、context7 (文档)、grep_app (GitHub 搜索) — 由插件运行时注入；在 `opencode mcp list` 中不可见（详见 [MCP 文档](docs/reference/features.md#native-vs-plugin-injected-mcps)）
- **会话工具**: 列出、读取、搜索和分析会话历史
- **生产力功能**: Ralph Loop、待办事项强制执行器、注释检查器、思考模式等
- **医生命令 (Doctor Command)**: 内置诊断 (`bunx oh-my-opencode doctor`) 验证插件注册、配置、模型和环境
- **模型回退**: `fallback_models` 可以在同一数组中混合普通模型字符串和每个回退的对象设置
- **文件提示词**: 在智能体配置中使用 `file://` 支持从文件加载提示词
- **会话恢复**: 自动从会话错误、上下文窗口限制和 API 故障中恢复
- **模型设置**: 智能体到模型的匹配已内置于 [安装指南](docs/guide/installation.md#step-5-understand-your-model-setup)

## 配置说明

默认配置带有强烈倾向，如果你坚持可以调整。

**快速概览：**
