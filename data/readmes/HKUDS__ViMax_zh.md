### 🎯 **端到端视频创作引擎**

**面临的挑战**：

- 🌅 **参考图像（Reference Images）**：获取、整理和对齐能够准确捕捉角色、物体、位置及环境的参考帧耗时且繁琐。

- 🫠 **一致性校验（Consistency Check）**：即使提供了正确的角色、位置、环境参考图像和提示词，图像生成器有时仍可能生成不可用的图像。

- 📄 **剧本生成（Scripts Generation）**：专业且高质量的视频需要具备丰富的信息密度与结构化设计。

- 📝 **分镜设计（Storyboard Design）**：将故事转化为视觉叙事需要摄影、场景构图和视觉讲故事的专业知识，而这正是大多数创作者所欠缺的。

- 🎬 **镜头设计（Shot Design）**：创建连贯的摄像机序列，包含恰当的视角、转场和节奏，同时在复杂场景中保持叙事流畅。

- 🎨 **开发延迟（Development Delays）**：在长篇内容中确保角色外观、环境和艺术风格在数百个镜头中保持一致。

- ⏱️ **制作效率（Production Efficiency）**：传统视频创作涉及多位专家与冗长的工作流，为独立创作者和快速原型开发设置了门槛。

- 🎥 **扩展 AI 生成视频（Scaling AI Generated Video）**：AI 生成的视频通常仅几秒长，高质量长达数分钟甚至小时的视频需要复杂的跨场景连贯性以及多分镜设计与处理能力。


**ViMax**：通过自动化从叙事输入到最终视频输出的整个创作流程，彻底消除这些制作瓶颈。

## 🏗️ 架构设计

### 📊 **系统概览**

**ViMax** 是一个多 Agent 视频框架，能够在确保角色和场景一致性的前提下实现自动化多镜头视频生成。我们的系统将你的创意无缝转化为对应视频，让你专注于叙事创作而非技术实现。

🎯 **核心技术能力**：

🧬 **智能长剧本生成（Intelligent Long Script Generation）**

基于 RAG 的长剧本设计引擎，能够智能分析长篇类小说故事，并自动将其划分为多场景剧本格式。该过程精细确保所有关键情节发展和角色对话在新结构中准确保留。

🪄 **表现力分镜设计（Expressive Storyboard Design）**

基于用户需求和目标受众，通过摄影语言创建富有表现力的分镜的镜头级分镜设计系统，为后续视频生成奠定叙事节奏。

🔮 **多机位拍摄模拟（Multi-camera Filming Simulation）**

模拟多机位拍摄，在保持同一场景内角色定位和背景一致的同时，提供沉浸式观看体验。

🧸 **智能参考图像选择（Intelligent Reference Images Selection）**

智能选择当前视频首帧所需的参考图像，包括时间轴上已生成的分镜，以确保随着视频变长，多个角色和环境元素的准确性。

⚙️ **自动化图像生成（Automated Images Generation）**

基于选定的参考图像和上一时间轴的视觉逻辑顺序，自动生成图像生成器的提示词（prompt），以合理布置角色与环境之间的空间交互位置。

✅ **自动化图像一致性校验（Automated Image Generation Consistency Check）**

并行生成多张图像，并通过 MLLM/VLM 选择一致性最佳的图像作为首帧，模拟人类创作者的工作流。

⚡ **高效并行镜头生成（High-efficiency Parallel Shot Generation）**

对同一摄像机拍摄的连续镜头进行并行处理，实现高效的视频制作。

## 🚀快速开始

### 🖥️ **运行环境**

```
OS: Linux, Windows
```

### 📥 **克隆与安装**
我们使用 `uv` 管理环境。如需安装 `uv`，请参考官方文档：https://docs.astral.sh/uv/getting-started/installation/.
```bash
git clone https://github.com/HKUDS/ViMax.git
cd ViMax
uv sync
```


### 🎯 **使用方法**
运行 `main_idea2video.py` 可将你的创意转化为视频。
你需要在 `configs/idea2video.yaml` 文件中配置模型和 API Key 信息，包含三个部分——对话模型、图像生成器和视频生成器，如下所示：
```yaml
chat_model:
  init_args:
    model: google/gemini-2.5-flash-lite-preview-09-2025
    model_provider: openai
    api_key: <YOUR_API_KEY>
    base_url: https://openrouter.ai/api/v1

image_generator:
  class_path: tools.ImageGeneratorNanobananaGoogleAPI
  init_args:
    api_key: <YOUR_API_KEY>

video_generator:
  class_path: tools.VideoGeneratorVeoGoogleAPI
  init_args:
    api_key: <YOUR_API_KEY>

working_dir: .working_dir/idea2video
```

随后，在 `main_idea2video.py` 中提供一个简洁而富有创意的想法及相应的创作要求。
```bash
idea = \
"""
If a cat and a dog are best friends, what would happen when they meet a new cat?
"""
user_requirement = \
"""
For children, do not exceed 3 scenes.
"""
style = "Cartoon"
```

#### 使用 MiniMax 作为对话模型提供商

[MiniMax](https://www.minimaxi.com/) 模型可作为替代的对话模型提供商。MiniMax 提供与 OpenAI 兼容的 API 访问，支持 **MiniMax-M3**（最新版）和 **MiniMax-M2.7**（100万上下文窗口）等模型。

只需在配置中设置 `model_provider: minimax`，基础 URL 将自动解析：
```yaml
chat_model:
  init_args:
    model: MiniMax-M3
    model_provider: minimax
    api_key: <YOUR_MINIMAX_API_KEY>
```

或者将 API Key 导出为环境变量，并将 `api_key` 留空：
```bash
export MINIMAX_API_KEY=<YOUR_KEY>
```

完整示例请参考 `configs/idea2video_minimax.yaml` 和 `configs/script2video_minimax.yaml`。

| 模型名称 | 说明 |
|---|---|
| MiniMax-M3 | 最新版本，推荐选用 |
| MiniMax-M2.7 | 上一代模型，支持 100万上下文 |
| MiniMax-M2.7-highspeed | M2.7 的快速变体 |

你同样需要在 `configs/script2video.yaml` 文件中配置 API。随后，在 `main_script2video.py` 中提供场景剧本及相应的创作要求，如下所示：
```python
script = \
"""
EXT. SCHOOL GYM - DAY
A group of students are practicing basketball in the gym. The gym is large and open, with a basketball hoop at one end and a large crowd of spectators at the other end. John (18, male, tall, athletic) is the star player, and he is practicing his dribble and shot. Jane (17, female, short, athletic) is the assistant coach, and she is helping John with his practice. The other students are watching the practice and cheering for John.
John: (dribbling the ball) I'm going to score a basket!
Jane: (smiling) Good job, John!
John: (shooting the ball) Yes!
...
"""
user_requirement = \
"""
Fast-paced with no more than 20 shots.
"""
style = "Animate Style"
```
