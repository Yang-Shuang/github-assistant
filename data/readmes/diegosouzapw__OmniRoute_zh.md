# 🎯 组合（Combos）—— 核心功能

</div>

> **组合（Combo）** 是 OmniRoute 自动路由的模型链。当配额用尽、提供商故障或成本飙升时，组合会自动无缝切换到下一个模型。**这正是 OmniRoute 坚不可摧的原因。** 🛡️

### ⚡ 零配置 —— 直接使用 `auto`

无需手动创建组合。将你的模型设置为 `auto`（或其变体），OmniRoute 会根据你已连接的提供商实时评分并构建虚拟组合：

| Model ID       | 优化目标                                          |
| -------------- | -------------------------------------------------------------- |
| `auto`         | 🎯 平衡默认值（LKGP —— 优先使用你上次表现良好的提供商） |
| `auto/coding`  | 🧑‍💻 代码生成质量优先权重                   |
| `auto/fast`    | ⚡ 最低延迟优先                                        |
| `auto/cheap`   | 💰 单 token 成本最低优先                                    |
| `auto/offline` | 🔋 剩余配额 / 速率限制余量最大优先                      |
| `auto/smart`   | 🔭 质量优先 + 10% 探索率以发现更优模型   |

##

### 🔀 或手动构建 —— 14 种路由策略

| 目标                                    | 策略 / 组合                                   |
| --------------------------------------- | -------------------------------------------------- |
| 🥇 在付费前耗尽订阅额度  | `priority` / `fill-first`                          |
| ⚖️ 跨账户均衡负载          | `round-robin` · `weighted` · `p2c` · `least-used`  |
| 💸 始终选择最经济的可用模型         | `cost-optimized` · `auto/cheap`                    |
| 🧠 在不同模型间接力长上下文（Context） | `context-relay` · `context-optimized`              |
| 🎲 随机化 / 隐私路由         | `random` · `strict-random`                         |
| 🤖 智能化决策                   | `auto`（9 因素评分）· `lkgp` · `reset-aware` |

<sub>自动组合引擎对每个候选模型进行 **9 项因子** 评分（健康状态、配额、成本、延迟、成功率、新鲜度…）—— 详见 [`docs/routing/AUTO-COMBO.md`](docs/routing/AUTO-COMBO.md)。</sub>

##

### 🧱 韧性内置于架构中（3 层独立防护）

| 层级                      | 作用域             | 功能                                                               |
| -------------------------- | ----------------- | -------------------------------------------------------------------------- |
| 🔌 **熔断器（Circuit breaker）**     | 整个提供商    | 停止持续请求上游故障的提供商；自动探测以恢复连接 |
| 💤 **连接冷却期** | 单个账户 / Key | 跳过被限流的 Key，同时其他 Key 继续提供服务                     |
| 🎯 **模型锁定（Model lockout）**       | 特定提供商 + 模型  | 仅隔离配额耗尽的单一模型，不影响整个连接         |

```
Combo: "always-on"                         Strategy: priority
  1. cc/claude-opus-4-7   ← subscription (用尽额度)
  2. cx/gpt-5.5           ← second subscription
  3. glm/glm-5.1          ← cheap backup ($0.5/1M)
  4. kr/claude-sonnet-4.5 ← FREE, unlimited (永不失败)
Result: 4 层降级 = 零停机
```

# 🔒 隐私优先 & 本地部署

</div>

> 你的密钥，你的机器，你的数据。OmniRoute 是一个**本地代理（Local Proxy）** —— 绝不会向外部回传数据。

- 🏠 **100% 运行在你的硬件上** —— npm、Docker、桌面端或手机。请求路径中无 OmniRoute 云端节点介入。
- 🔐 **凭据静态加密** —— API Key & OAuth Token 使用 **AES-256-GCM** 密封存储。
- 🚫 **默认零遥测（Telemetry）** —— 你的提示词仅发送到你选择的提供商， nowhere else.
- 🛡️ **加固网关** —— API-Key 作用域限制、IP 过滤、速率限制、提示注入防护、仅限回环地址的进程路由。
- 📜 **MIT 开源许可** —— 审计每一行代码，永久自托管。

# 🗜️ 自动节省 15–95% Token

</div>

> **既然少用也能解决问题，何必浪费大量 Token？** 每个请求都会透明地经过 OmniRoute 的压缩管道 —— 无需修改客户端。它融合了 [RTK](https://github.com/rtk-ai/rtk)、[Caveman](https://github.com/JuliusBrussee/caveman)（⭐ 51K+）和 [Troglodita](https://github.com/leninejunior/troglodita)（PT-BR）的思路。

| Mode                           | Savings    | Best for                    |
| ------------------------------ | ---------- | --------------------------- |
| 🪶 **Lite**                    | ~15%       | 始终开启的安全默认值      |
| 🪨 **Standard (Caveman)**      | ~30%       | 日常编码                |
| ⚡ **Aggressive**              | ~50%       | 长工具密集型会话    |
| 🔥 **Ultra**                   | ~75%       | 最大节省             |
| 🧰 **RTK**                     | 60–90%     | Shell/测试/构建/git 输出 |
| 🔗 **Stacked (RTK → Caveman)** | **78–95%** | 混合提示词 + 工具日志   |

**真实示例 —— Standard 模式：**

> **Before (69 tokens):** _"The reason your React component is re-rendering is likely because you're creating a new object reference on each render cycle. When you pass an inline object as a prop, React's shallow comparison sees it as a different object every time, which triggers a re-render. I would recommend using useMemo to memoize the object."_
>
> **After (19 tokens):** _"New object ref each render. Inline object prop = new ref = re-render. Wrap in useMemo."_
>
> **Same answer. 72% fewer tokens. Zero accuracy loss.** ✅

**PT-BR 示例 —— [Troglodita](https://github.com/leninejunior/troglodita) 模式：**

> **Antes (42 tokens):** _"O problema é que o componente está re-renderizando porque uma nova referência de objeto está sendo criada em cada ciclo de renderização. Eu recomendaria usar useMemo."_
>
> **Depois (12 tokens):** _"Re-render: ref nova cada ciclo (objeto inline recriado). Usar `useMemo`."_
>
> **Mesma resposta. ~70% menos tokens. Precisão técnica intacta.** ✅

<br/>

### 📖 工作原理 —— 管道、架构与节省数学计算</b></summary>

```
Client (10,000 tok) ──▶ OmniRoute Compression (7 options) ──▶ Provider (~1,080 tok, up to 95% saved)
```

默认叠加组合运行 `RTK → Caveman`。当两者同时作用于同一工具/上下文负载时，节省效果呈复合增长：

```txt
combined = 1 − (1 − RTK) × (1 − Caveman_input)
average  = 1 − (1 − 0.80) × (1 − 0.46) = 89.2%
range    = 78.4 – 94.6%
```

代码块、URL、JSON 和结构化数据始终受保留引擎保护。可通过 token 阈值自动触发压缩，或为每个路由组合分配独立的压缩管道。

📖 [`COMPRESSION_GUIDE.md`](docs/compression/COMPRESSION_GUIDE.md) · [`RTK_COMPRESSION.md`](docs/compression/RTK_COMPRESSION.md) · [`COMPRESSION_ENGINES.md`](docs/compression/COMPRESSION_ENGINES.md)

# ⚡ 快速开始

</div>

**1）安装并运行**

```bash
npm install -g omniroute
omniroute
```

仪表盘位于 `http://localhost:20128` · API 端点位于 `http://localhost:20128/v1`。

**2）连接免费提供商（无需注册）**

Dashboard → **Providers** → 连接 **Kiro AI**（无限免费 Claude）或 **OpenCode Free**（无需认证）→ 完成。

**3）指向你的编码工具**

```txt
Base URL: http://localhost:20128/v1
API Key:  [copy from Dashboard → Endpoints]
Model:    auto            (零配置智能路由 —— 或指定任意提供商/模型)
```

**4）验证是否正常工作**

```bash
curl http://localhost:20128/v1/models -H "Authorization: Bearer YOUR_KEY"
```

你应该能看到已连接的模型列表。🎉 完成 —— 开始编码，OmniRoute 会自动为你路由与降级。

## 🛠️ 技术栈

</div>

- **运行环境**：Node.js 20.20.2+、22.22.2+ 或 24.x LTS（推荐 24 LTS）
- **语言**：TypeScript 5.9 —— `src/` 和 `open-sse/` 下 **100% TypeScript**（自 v2.0 起核心模块零 `any`）
- **框架**：Next.js 16 + React 19 + Tailwind CSS 4
- **数据库**：better-sqlite3 (SQLite) + LowDB (JSON legacy) —— 领域状态、代理日志、MCP 审计、路由决策、记忆、技能
- **Schema 验证**：Zod（MCP 工具 I/O 验证、API 契约）
- **协议支持**：MCP (stdio/HTTP) + A2A v0.3 (JSON-RPC 2.0 + SSE)
- **流式传输**：Server-Sent Events (SSE) + WebSocket 桥接 (`/v1/ws`)
- **认证机制**：OAuth 2.0 (PKCE) + JWT + API Keys + MCP Scoped Authorization
- **测试**：Node.js test runner + Vitest (**4,690+ 测试用例**，覆盖 517 个文件 —— 单元测试、集成测试、E2E、安全、生态兼容)
- **多平台支持**：桌面端 (Electron)、Android (Termux)、PWA (任意浏览器)
