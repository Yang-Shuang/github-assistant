## 🌟 系统概览

*下一代多模态智能*

<div style="background: linear-gradient(135deg, #1a1a2e 0%, #16213e 50%, #0f3460 100%); border-radius: 15px; padding: 25px; margin: 20px 0; border: 2px solid #00d9ff; box-shadow: 0 0 30px rgba(0, 217, 255, 0.3);">

现代文档日益包含多样化的多模态内容——文本、图像、表格、公式、图表和多媒体等，而传统的以文本为主的 RAG 系统难以有效处理这些内容。**RAG-Anything** 针对这一挑战提供了解决方案，它是一个构建于 [LightRAG](https://github.com/HKUDS/LightRAG) 之上的综合性**全功能多模态文档处理 RAG 系统**。

作为一体化解决方案，RAG-Anything **无需依赖多种专用工具**。它在单一集成框架内提供**跨所有内容的无缝处理与查询功能**。与传统 RAG 方法在处理非文本元素时的局限性不同，我们的全功能系统提供了**全面的多模态检索能力**。

用户可以通过**统一的界面**查询包含**交错文本**、**视觉图表**、**结构化表格**和**数学公式**的文档。这种整合方法使 RAG-Anything 在学术研究、技术文档、财务报告和企业知识管理等领域尤为宝贵，因为这些场景中的丰富混合内容需要一个**统一的处理框架**。

</div>

- **🔄 端到端多模态流水线** - 从文档数据摄入与解析到智能多模态查询回答的完整工作流

### 1. 文档解析阶段

<div style="background: linear-gradient(90deg, #1a1a2e 0%, #16213e 100%); border-radius: 10px; padding: 20px; margin: 15px 0; border-left: 4px solid #4ecdc4;">

系统通过自适应内容分解提供高保真文档提取。它智能分割异构元素，同时保留上下文关系。通过专用的优化解析器实现通用格式兼容。

**关键组件：**

- **⚙️ MinerU 集成**：利用 [MinerU](https://github.com/opendatalab/MinerU) 进行高保真文档结构提取与语义保持，适用于复杂排版布局。

- **🧩 自适应内容分解**：自动将文档分割为连贯的文本块、视觉元素、结构化表格、数学公式及专用内容类型，同时保留上下文关系。

- **📁 通用格式支持**：通过专用的格式优化解析器，全面处理 PDF、Office 文档（DOC/DOCX/PPT/PPTX/XLS/XLSX）、图像及新兴格式。

</div>

### 2. 多模态内容理解与处理

<div style="background: linear-gradient(90deg, #16213e 0%, #0f3460 100%); border-radius: 10px; padding: 20px; margin: 15px 0; border-left: 4px solid #ff6b6b;">

系统自动对内容进行分类并路由至优化通道。采用并发流水线并行处理文本与多模态内容，在转换过程中保留文档层级结构与元素关系。

**关键组件：**

- **🎯 自主内容分类与路由**：自动识别、分类并通过优化的执行通道分发不同内容类型。

- **⚡ 并发多流水线架构**：通过专用处理流水线实现文本与多模态内容的并发执行。该方法在最大化吞吐效率的同时保留内容完整性。

- **🏗️ 文档层级提取**：在内容转换过程中提取并保留原始文档的层级结构与元素间关系。

</div>

### 3. 多模态分析引擎

<div style="background: linear-gradient(90deg, #0f3460 0%, #1a1a2e 100%); border-radius: 10px; padding: 20px; margin: 15px 0; border-left: 4px solid #00d9ff;">

系统部署了模态感知处理单元，用于处理异构数据模态：

**专用分析器：**

- **🔍 视觉内容分析器**：
  - 集成视觉模型进行图像分析。
  - 基于视觉语义生成上下文感知的描述性标题。
  - 提取视觉元素之间的空间关系与层级结构。

- **📊 结构化数据解释器**：
  - 对表格和结构化数据进行系统性解析。
  - 实现统计模式识别算法以进行数据趋势分析。
  - 识别多个数据集间的语义关系与依赖项。

- **📐 数学表达式解析器**：
  - 高精度解析复杂的数学表达式与公式。
  - 提供原生 LaTeX 格式支持，无缝对接学术工作流。
  - 建立数学方程与领域特定知识库之间的概念映射。

- **🔧 可扩展模态处理器**：
  - 为自定义和新兴内容类型提供可配置的框架。
  - 通过插件架构实现新模态处理器的动态集成。
  - 支持针对特定用例的运行时流水线配置。

</div>

### 4. 多模态知识图谱索引

<div style="background: linear-gradient(90deg, #1a1a2e 0%, #16213e 100%); border-radius: 10px; padding: 20px; margin: 15px 0; border-left: 4px solid #4ecdc4;">

多模态知识图谱构建模块将文档内容转换为结构化的语义表示。它提取多模态实体，建立跨模态关系，并保留层级组织。系统应用加权相关性评分以优化知识检索。

**核心功能：**

- **🔍 多模态实体提取**：将重要的多模态元素转化为结构化知识图谱实体。该过程包含语义标注与元数据保持。

- **🔗 跨模态关系映射**：通过自动关系推理算法，建立文本实体与多模态组件之间的语义连接与依赖关系。

- **🏗️ 层级结构保持**：通过 `belongs_to`（属于）关系链维持原始文档的组织结构。这些链条保留了逻辑内容层级与章节依赖关系。

- **⚖️ 加权关系评分**：为关系类型分配定量相关性分数。评分基于语义接近度与文档结构中的上下文重要性。

</div>

### 5. 模态感知检索

<div style="background: linear-gradient(90deg, #16213e 0%, #0f3460 100%); border-radius: 10px; padding: 20px; margin: 15px 0; border-left: 4px solid #ff6b6b;">

混合检索系统结合向量相似度搜索与图遍历算法，实现全面的内容检索。它实施模态感知排序机制，并维持检索元素间的关系连贯性，以确保上下文整合的信息交付。

**检索机制：**

- **🔀 向量-图谱融合**：集成向量相似度搜索与图遍历算法。该方法同时利用语义嵌入与结构关系进行综合内容检索。

- **📊 模态感知排序**：实施自适应评分机制，根据内容类型相关性对检索结果加权。系统会根据查询特定的模态偏好调整排名。

- **🔗 关系连贯性保持**：维持检索元素间的语义与结构关系。这确保了信息交付的连贯性与上下文完整性。

</div>

### 安装指南

#### 方式一：从 PyPI 安装（推荐）

```bash
# 基础安装
pip install raganything

# 包含可选依赖以扩展格式支持：
pip install 'raganything[all]'              # 所有可选功能
pip install 'raganything[image]'            # 图像格式转换 (BMP, TIFF, GIF, WebP)
pip install 'raganything[text]'             # 文本文件处理 (TXT, MD)
pip install 'raganything[image,text]'       # 多项功能组合
```

#### 方式二：从源码安装
```bash
# 安装 uv（如尚未安装）
curl -LsSf https://astral.sh/uv/install.sh | sh

# 克隆并设置项目环境
git clone https://github.com/HKUDS/RAG-Anything.git
cd RAG-Anything

# 在虚拟环境中安装包及依赖项
uv sync

# 如果遇到网络超时（尤其是 opencv 包）：
# UV_HTTP_TIMEOUT=120 uv sync

# 直接使用 uv 运行命令（推荐方式）
uv run python examples/raganything_example.py --help

# 安装可选依赖
uv sync --extra image --extra text  # 指定功能
uv sync --all-extras                 # 所有可选功能
```

#### 可选依赖说明

- **`[image]`** - 启用 BMP、TIFF、GIF、WebP 图像格式处理（需 Pillow）
- **`[text]`** - 启用 TXT 和 MD 文件处理（需 ReportLab）
- **`[all]`** - 包含所有 Python 可选依赖项

> **⚠️ Office 文档处理要求：**
> - Office 文档 (.doc, .docx, .ppt, .pptx, .xls, .xlsx) 需要安装 **LibreOffice**
> - 下载地址：[LibreOffice 官方网站](https://www.libreoffice.org/download/download/)
> - **Windows**：从官网下载安装程序
> - **macOS**：`brew install --cask libreoffice`
> - **Ubuntu/Debian**：`sudo apt-get install libreoffice`
> - **CentOS/RHEL**：`sudo yum install libreoffice`

**检查 MinerU 安装状态：**

```bash
# 验证安装
mineru --version

# 检查配置是否正确
python -c "from raganything import RAGAnything; rag = RAGAnything(); print('✅ MinerU 已正确安装' if rag.check_parser_installation() else '❌ MinerU 安装存在问题')"
```

模型将在首次使用时自动下载。如需手动下载，请参考 [MinerU 模型源配置](https://github.com/opendatalab/MinerU/blob/master/README.md#22-model-source-configuration)。

### 使用示例

#### 1. 端到端文档处理

```python
import asyncio
from functools import partial
from raganything import RAGAnything, RAGAnythingConfig
from lightrag.llm.openai import openai_complete_if_cache, openai_embed
from lightrag.utils import EmbeddingFunc

async def main():
    # 设置 API 配置
    api_key = "your-api-key"
    base_url = "your-base-url"  # 可选

    # 创建 RAGAnything 配置
    config = RAGAnythingConfig(
        working_dir="./rag_storage",
        parser="mineru",  # 解析器选择：mineru, docling, 或 paddleocr
        parse_method="auto",  # 解析方法：auto, ocr, 或 txt
        enable_image_processing=True,
        enable_table_processing=True,
        enable_equation_processing=True,
    )

    # 定义 LLM 模型函数
    def llm_model_func(prompt, system_prompt=None, history_messages=[], **kwargs):
        return openai_complete_if_cache(
            "gpt-4o-mini",
            prompt,
            system_prompt=system_prompt,
            history_messages=history_messages,
            api_key=api_key,
            base_url=base_url,
            **kwargs,
        )

    # 定义用于图像处理的视觉模型函数
    def vision_model_func(
        prompt, system_prompt=None, history_messages=[], image_data=None, messages=None, **kwargs
    ):
        # 如果提供了 messages 格式（用于多模态 VLM 增强查询），则直接使用
        if messages:
            return openai_complete_if_cache(
                "gpt-4o",
                "",
                system_prompt=None,
                history_messages=[],
                messages=messages,
                api_key=api_key,
                base_url=base_url,
                **kwargs,
            )
        # 传统单图格式
        elif image_data:
            return openai_complete_if_cache(
                "gpt-4o",
                "",
                system_prompt=None,
                history_messages=[],
                messages=[
                    {"role": "system", "content": system_prompt}
                    if system_prompt
                    else None,
                    {
                        "role": "user",
                        "content": [
                            {"type": "text", "text": prompt},
                            {
                                "type": "image_url",
                                "image_url": {
                                    "url": f"data:image/jpeg;base64,{image_data}"
                                },
                            },
                        ],
                    }
                    if image_data
                    else {"role": "user", "content": prompt},
                ],
                api_key=api_key,
                base_url=base_url,
                **kwargs,
            )
        # 纯文本格式
        else:
            return llm_model_func(prompt, system_prompt, history_messages, **kwargs)

    # 定义嵌入函数
    embedding_func = EmbeddingFunc(
        embedding_dim=3072,
        max_token_size=8192,
        func=partial(
            openai_embed.func,
            model="text-embedding-3-large",
            api_key=api_key,
            base_url=base_url,
        ),
    )

    # 初始化 RAGAnything
    rag = RAGAnything(
        config=config,
```

**内容列表格式规范：**

`content_list` 应遵循标准格式，每个项目均为包含以下字段的字典：

- **文本内容**：`{"type": "text", "text": "内容文本", "page_idx": 0}`
- **图像内容**：`{"type": "image", "img_path": "/绝对路径/to/image.jpg", "image_caption": ["标题"], "image_footnote": ["注释"], "page_idx": 1}`
- **表格内容**：`{"type": "table", "table_body": "Markdown 格式表格", "table_caption": ["标题"], "table_footnote": ["注释"], "page_idx": 2}`
- **公式内容**：`{"type": "equation", "latex": "LaTeX 公式", "text": "描述文本", "page_idx": 3}`
- **通用内容**：`{"type": "custom_type", "content": "任意内容", "page_idx": 4}`

**重要注意事项：**
- **`img_path`**：必须是图像文件的绝对路径（例如 `/home/user/images/chart.jpg` 或 `C:\Users\user\images\chart.jpg`）
- **`page_idx`**：表示该内容在原始文档中出现的页码（索引从 0 开始）
- **内容顺序**：系统将严格按照列表中的出现顺序进行处理

此方法特别适用于以下场景：
- 你拥有来自外部解析器的内容（非 MinerU/Docling）
- 希望处理程序化生成的内容
- 需要将多个来源的内容插入到单一知识库中
- 拥有缓存的解析结果并希望重复使用

> **提示**：API Key 仅在使用 LLM 集成进行完整 RAG 处理时需要。解析测试文件（`office_document_test.py` 和 `image_format_test.py`）仅测试解析器功能，无需 API Key。

### 故障排查与多模态检查清单

- 请参阅 **[docs/multimodal_rag_failure_modes.md](docs/multimodal_rag_failure_modes.md)** 获取常见流水线问题的简要检查清单（OCR、表格、检索偏差、调试技巧）。相关议题：[#207](https://github.com/HKUDS/RAG-Anything/issues/207), [#213](https://github.com/HKUDS/RAG-Anything/issues/213)。

### 公共媒体 URL（CDN / 对象存储）

当数据摄入运行在服务器上，但你的 UI 或其他服务需要 **HTTPS**（或 S3 风格）链接来访问图表时，请设置：

```bash
# 资源基础 URL（无需末尾斜杠）
RAGANYTHING_PUBLIC_ASSET_BASE_URL=https://my-bucket.s3.us-east-1.amazonaws.com/prefix
# 应从该树下的绝对路径中剥离的文件系统根目录
RAGANYTHING_PUBLIC_ASSET_STRIP_PREFIX=/var/rag/output
```

解析完成后，每个非空的 `img_path`、`table_img_path` 或 `equation_img_path` 可能会获得一个同级的 `*_public_url` 字段，而原始路径仍保留在磁盘上用于本地处理。详见 [#272](https://github.com/HKUDS/RAG-Anything/issues/272)。

> **当前作用域**：此映射仅在 MinerU 解析器路径中运行。其他解析器（如 Docling）将继续正常工作，但直到辅助程序也集成到其 `content_list` 后处理流程之前，不会生成 `*_public_url` 字段。如果仅设置了两个环境变量中的一个，RAG-Anything 将记录警告并跳过 URL 附加操作。

### 解析器配置

RAGAnything 现已支持多种解析器，每种均有特定优势：

#### MinerU 解析器
- 支持 PDF、图像、Office 文档及更多格式
- 强大的 OCR 与表格提取能力
- 支持 GPU 加速

#### Docling 解析器
- 针对 Office 文档和 HTML 文件优化
- 更好的文档结构保持效果
- 原生支持多种 Office 格式

#### PaddleOCR 解析器
- 专注于图像和 PDF 的 OCR 解析器
- 生成兼容现有 `content_list` 处理的文本块
- 支持通过先转换为 PDF 来可选处理 Office/TXT/MD 文件

安装 PaddleOCR 解析器扩展：

```bash
pip install -e ".[paddleocr]"
# 或
uv sync --extra paddleocr
```

> **注意**：PaddleOCR 还需要 `paddlepaddle`（CPU/GPU 包因平台而异）。请通过官方指南安装：https://www.paddlepaddle.org.cn/install/quick

### MinerU 配置

```bash
# MinerU 2.0 使用命令行参数替代配置文件
# 查看可用选项：
mineru --help

# 常用配置示例：
mineru -p input.pdf -o output_dir -m auto    # 自动解析模式
mineru -p input.pdf -o output_dir -m ocr     # OCR 专注解析
mineru -p input.pdf -o output_dir -b pipeline --device cuda  # GPU 加速
```

你也可通过 RAGAnything 参数进行配置：

```python
# 基础解析配置（含解析器选择）
await rag.process_document_complete(
    file_path="document.pdf",
    output_dir="./output/",
    parse_method="auto",          # 或 "ocr", "txt"
    parser="mineru"               # 可选："mineru", "docling", 或 "paddleocr"
)

# 高级解析配置（含特殊参数）
await rag.process_document_complete(
    file_path="document.pdf",
    output_dir="./output/",
    parse_method="auto",          # 解析方法："auto", "ocr", "txt"
    parser="mineru",              # 解析器选择："mineru", "docling", 或 "paddleocr"

    # MinerU 特殊参数 - 所有支持的 kwargs：
    lang="ch",                   # 文档语言（用于 OCR 优化，如 "ch", "en", "ja"）
    device="cuda:0",             # 推理设备："cpu", "cuda", "cuda:0", "npu", "mps"
    start_page=0,                # 起始页码（基于 0，适用于 PDF）
    end_page=10,                 # 结束页码（基于 0，适用于 PDF）
    formula=True,                # 启用公式解析
    table=True,                  # 启用表格解析
    backend="pipeline",          # 解析后端：pipeline|hybrid-auto-engine|hybrid-http-client|vlm-auto-engine|vlm-http-client.
    source="huggingface",        # 模型来源："huggingface", "modelscope", "local"
    # vlm_url="http://127.0.0.1:3000" # 使用 backend=vlm-http-client 时的服务地址

    # 标准 RAGAnything 参数
    display_stats=True,          # 显示内容统计信息
    split_by_character=None,     # 可选：按指定字符分割文本
    doc_id=None                  # 可选：文档 ID
)
```

> **注意**：MinerU 2.0 不再使用 `magic-pdf.json` 配置文件。所有设置现在均作为命令行参数或函数参数传递。RAG-Anything 支持多种文档解析器，包括 MinerU、Docling 和 PaddleOCR。

### 处理要求

不同内容类型需要特定的可选依赖项：

- **Office 文档** (.doc, .docx, .ppt, .pptx, .xls, .xlsx)：安装 [LibreOffice](https://www.libreoffice.org/download/download/)
- **扩展图像格式** (.bmp, .tiff, .gif, .webp)：使用 `pip install raganything[image]` 安装
- **文本文件** (.txt, .md)：使用 `pip install raganything[text]` 安装
- **PaddleOCR 解析器** (`parser="paddleocr"`)：使用 `pip install raganything[paddleocr]` 安装，随后为你的平台安装 `paddlepaddle`

> **📋 快速安装**：使用 `pip install raganything[all]` 启用所有格式支持（仅限 Python 依赖项 - LibreOffice 仍需单独安装）

## 🧪 支持的内容类型

### 文档格式

- **PDFs** - 研究论文、报告、演示文稿
- **Office 文档** - DOC, DOCX, PPT, PPTX, XLS, XLSX
- **图像** - JPG, PNG, BMP, TIFF, GIF, WebP
- **文本文件** - TXT, MD

### 多模态元素

- **图像** - 照片、图表、示意图、截图
- **表格** - 数据表、对比图、统计摘要
- **公式** - LaTeX 格式的数学公式
- **通用内容** - 通过可扩展处理器支持自定义内容类型

*如需安装特定格式依赖项，请参阅 [配置](#-configuration) 部分。*
