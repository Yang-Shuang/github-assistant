## 为什么选择 CC Switch？

现代 AI 编程依赖 Claude Code、Codex、Gemini CLI、OpenCode 和 OpenClaw 等命令行工具，但它们的配置格式各不相同。切换 API 提供商意味着需要手动编辑 JSON、TOML 或 `.env` 文件，且目前缺乏统一管理多个工具的 MCP（Model Context Protocol）和技能（Skills）的方法。

**CC Switch** 提供了一款统一的桌面应用来管理这五个 CLI 工具。你无需手动编辑配置文件，而是可以通过可视化界面一键导入提供商配置、即时切换、内置 50+ 种预设配置、统一管理 MCP 和技能（Skills），并支持系统托盘快速切换——所有数据均基于可靠的 SQLite 数据库进行原子写入，有效防止配置文件损坏。

- **一个应用，管理五个 CLI 工具** — 从单一界面管理 Claude Code、Codex、Gemini CLI、OpenCode 和 OpenClaw
- **告别手动编辑** — 内置 AWS Bedrock、NVIDIA NIM 及社区代理等 50+ 种提供商预设；只需选择并切换即可
- **统一的 MCP 与技能管理** — 一个面板即可跨四个应用管理 MCP 服务器和技能（Skills），支持双向同步
- **系统托盘快速切换** — 从托盘菜单即时切换提供商，无需打开完整应用界面
- **云端同步** — 通过 Dropbox、OneDrive、iCloud 或 WebDAV 服务器在设备间同步提供商数据

## 常见问题 (FAQ)

<details>
<summary><strong>CC Switch 支持哪些 AI 命令行工具？</strong></summary>

CC Switch 支持五个工具：**Claude Code**、**Codex**、**Gemini CLI**、**OpenCode** 和 **OpenClaw**。每个工具都配有专属的提供商预设与配置管理功能。

</details>

<details>
<summary><strong>切换提供商后需要重启终端吗？</strong></summary>

对于大多数工具，是的——请重启终端或对应的 CLI 工具以使更改生效。**Claude Code** 是例外，目前它支持在不重启的情况下热切换提供商数据。

</details>

<details>
<summary><strong>切换提供商后我的插件配置消失了，发生了什么？</strong></summary>

CC Switch 提供了“共享配置片段（Shared Config Snippet）”功能，用于在提供商之间传递除 API Key 和端点之外的公共数据。前往“编辑提供商” → “共享配置面板” → 点击“从当前提供商提取”，即可保存所有公共数据。创建新提供商时，勾选“写入共享配置”（默认已开启），插件数据便会包含在新提供商中。你首次启动应用时导入的默认提供商会保留所有你的配置项。

</details>

<details>
<summary><strong>macOS 安装指南</strong></summary>

CC Switch for macOS 已由 Apple 代码签名与公证。你可以直接下载并安装，无需额外步骤。推荐使用 `.dmg` 安装包。

</details>

<details>
<summary><strong>为什么无法删除当前正在使用的提供商？</strong></summary>

CC Switch 遵循“最小侵入”设计原则——即使你卸载了本应用，你的 CLI 工具仍会保持正常工作状态。系统始终保留一个活动配置，因为如果删除所有配置，对应的 CLI 工具将无法使用。如果你很少使用某个特定 CLI 工具，可以在设置中将其隐藏。如需切换回官方登录方式，请参阅下一个问题。

</details>

<details>
<summary><strong>如何切换回官方登录方式？</strong></summary>

从预设列表中添加入一个“官方登录”提供商。切换到该配置后，运行登出/重新登录流程，之后即可在官方提供商与第三方提供商之间自由切换。Codex 支持在不同官方提供商间切换，方便你轻松管理多个 Plus 或 Team 账号。

</details>

<details>
<summary><strong>我的数据存储在哪里？</strong></summary>

- **数据库**: `~/.cc-switch/cc-switch.db` (SQLite — 存储提供商、MCP、提示词、技能)
- **本地设置**: `~/.cc-switch/settings.json` (设备级 UI 偏好设置)
- **备份文件**: `~/.cc-switch/backups/` (自动轮转，保留最近 10 份)
- **技能文件**: `~/.cc-switch/skills/` (默认符号链接至对应应用目录)
- **技能备份**: `~/.cc-switch/skill-backups/` (卸载前自动创建，保留最近 20 份)

</details>

<details>
<summary><strong>架构概览</strong></summary>

### 设计原则

```
┌─────────────────────────────────────────────────────────────┐
│                    Frontend (React + TS)                    │
│  ┌─────────────┐  ┌──────────────┐  ┌──────────────────┐    │
│  │ Components  │  │    Hooks     │  │  TanStack Query  │    │
│  │   (UI)      │──│ (Bus. Logic) │──│   (Cache/Sync)   │    │
│  └─────────────┘  └──────────────┘  └──────────────────┘    │
└────────────────────────┬────────────────────────────────────┘
                         │ Tauri IPC
┌────────────────────────▼────────────────────────────────────┐
│                  Backend (Tauri + Rust)                     │
│  ┌─────────────┐  ┌──────────────┐  ┌──────────────────┐    │
│  │  Commands   │  │   Services   │  │  Models/Config   │    │
│  │ (API Layer) │──│ (Bus. Layer) │──│     (Data)       │    │
│  └─────────────┘  └──────────────┘  └──────────────────┘    │
└─────────────────────────────────────────────────────────────┘
```

**核心设计模式**

- **SSOT（单一事实来源）**：所有数据统一存储于 `~/.cc-switch/cc-switch.db` (SQLite)
- **双层存储架构**：可同步数据使用 SQLite，设备级设置使用 JSON
- **双向同步机制**：切换时写入实时文件，编辑活动提供商时从实时文件回写（backfill）
- **原子写入**：采用临时文件+重命名模式，防止配置文件损坏
- **并发安全**：通过 Mutex 保护数据库连接，避免竞态条件
- **分层架构**：清晰分离 Commands → Services → DAO → Database

**关键组件**

- **ProviderService**: 提供商 CRUD、切换、回写与排序
- **McpService**: MCP 服务器管理、导入/导出、实时文件同步
- **ProxyService**: 本地代理模式，支持热切换与格式转换
- **SessionManager**: 跨所有支持应用浏览对话历史
- **ConfigService**: 配置导入/导出、备份轮转
- **SpeedtestService**: API 端点延迟测试

</details>
