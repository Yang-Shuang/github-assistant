## 🌟 功能特性

- **AI 优化**：以易于 AI 理解和处理的方式格式化你的代码库。
- **Token 计数**：提供每个文件及整个仓库的 Token（词元）数量，便于管理 LLM 上下文限制。
- **简单易用**：只需一条命令即可打包整个仓库。
- **高度可定制**：轻松配置包含或排除的文件。
- **感知 Git**：自动遵循 `.gitignore`、`.ignore` 和 `.repomixignore` 文件规则。
- **安全优先**：集成 [Secretlint](https://github.com/secretlint/secretlint) 进行严格的安全检查，检测并防止敏感信息泄露。
- **代码压缩**：`--compress` 选项使用 [Tree-sitter](https://github.com/tree-sitter/tree-sitter) 提取关键代码元素，在保留结构的同时减少 Token 数量。

### 使用 CLI 工具 `>_`

无需安装即可在项目目录中即时试用 Repomix：

```bash
npx repomix@latest
```

或全局安装以便重复使用：

```bash
# 使用 npm 安装
npm install -g repomix

# 或使用 yarn
yarn global add repomix

# 或使用 bun
bun add -g repomix

# 或使用 Homebrew（macOS/Linux）
brew install repomix

# 然后在任意项目目录中运行
repomix
```

就是这样！Repomix 将在当前目录生成一个 `repomix-output.xml` 文件，以 AI 友好的格式包含你的整个仓库。

随后可将该文件发送给 AI 助手，并附上如下提示词：

```
This file contains all the files in the repository combined into one.
I want to refactor the code, so please review it first.
```

## 📊 使用方法

打包整个仓库：

```bash
repomix
```

打包指定目录：

```bash
repomix path/to/directory
```

使用 [glob 模式](https://github.com/mrmlnc/fast-glob?tab=readme-ov-file#pattern-syntax) 打包特定文件或目录：

```bash
repomix --include "src/**/*.ts,**/*.md"
```

排除特定文件或目录：

```bash
repomix --ignore "**/*.log,tmp/"
```

打包远程仓库：

```bash
repomix --remote https://github.com/yamadashy/repomix

# 你也可以使用 GitHub 简写格式：
repomix --remote yamadashy/repomix

# 你可以指定分支名称、标签或提交哈希：
repomix --remote https://github.com/yamadashy/repomix --remote-branch main

# 或使用特定的提交哈希：
repomix --remote https://github.com/yamadashy/repomix --remote-branch 935b695

# 另一种便捷方式是指定分支的 URL
repomix --remote https://github.com/yamadashy/repomix/tree/main

# 提交的 URL 也受支持
repomix --remote https://github.com/yamadashy/repomix/commit/836abcd7335137228ad77feb28655d85712680f1

```

通过文件列表（管道输入）打包文件：

```bash
# 使用 find 命令
find src -name "*.ts" -type f | repomix --stdin

# 使用 git 获取已跟踪的文件
git ls-files "*.ts" | repomix --stdin

# 使用 grep 查找包含特定内容的文件
grep -l "TODO" **/*.ts | repomix --stdin

# 使用 ripgrep 查找包含特定内容的文件
rg -l "TODO|FIXME" --type ts | repomix --stdin

# 使用 ripgrep (rg) 查找文件
rg --files --type ts | repomix --stdin

# 使用 sharkdp/fd 查找文件
fd -e ts | repomix --stdin

# 使用 fzf 从所有文件中选择
fzf -m | repomix --stdin

# 结合 fzf 进行交互式文件选择
find . -name "*.ts" -type f | fzf -m | repomix --stdin

# 使用 ls 配合 glob 模式
ls src/**/*.ts | repomix --stdin

# 从包含文件路径的文件中读取
cat file-list.txt | repomix --stdin

# echo 直接输入
echo -e "src/index.ts\nsrc/utils.ts" | repomix --stdin
```

`--stdin` 选项允许你将文件路径列表传递给 Repomix，让你在选择要打包的文件时拥有极大的灵活性。

使用 `--stdin` 时，指定的文件实际上会被添加到包含模式中。这意味着正常的包含和忽略行为仍然适用——通过 stdin 指定的文件如果匹配到忽略模式，仍会被排除。

> [!NOTE]
> 使用 `--stdin` 时，文件路径可以是相对或绝对路径，Repomix 会自动处理路径解析与去重。

在输出中包含 Git 日志：

```bash
# 包含默认数量的 git 日志（50 次提交）
repomix --include-logs

# 包含指定数量的 git 日志
repomix --include-logs --include-logs-count 10

# 结合 diff 以获取全面的 git 上下文
repomix --include-logs --include-diffs
```

Git 日志包含每次提交的日期、消息和文件路径，为 AI 分析代码演进和开发模式提供宝贵的上下文。

压缩输出：

```bash
repomix --compress

# 你也可以配合远程仓库使用：
repomix --remote yamadashy/repomix --compress
```

初始化新的配置文件 (`repomix.config.json`)：

```bash
repomix --init
```

生成打包文件后，即可配合 ChatGPT、DeepSeek、Perplexity、Gemini、Gemma、Llama、Grok 等生成式 AI 工具使用。

### 输出文件格式

Repomix 生成单个文件，并在代码库的不同部分之间添加清晰的分隔符。  
为提升 AI 的理解能力，输出文件开头包含面向 AI 的说明，使模型更容易理解打包仓库的上下文与结构。

#### XML 格式（默认）

XML 格式以层级方式组织内容：

```xml
This file is a merged representation of the entire codebase, combining all repository files into a single document.

<file_summary>
  (Metadata and usage AI instructions)
</file_summary>

<directory_structure>
src/
cli/
cliOutput.ts
index.ts

(...remaining directories)
</directory_structure>

<files>
<file path="src/index.js">
  // File contents here
</file>

(...remaining files)
</files>

<instruction>
(Custom instructions from `output.instructionFilePath`)
</instruction>
```

对 AI 语境下 XML 标签潜力感兴趣的用户可参考：  
https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/use-xml-tags

> When your prompts involve multiple components like context, instructions, and examples, XML tags can be a game-changer. They help Claude parse your prompts more accurately, leading to higher-quality outputs.

这意味着 Repomix 的 XML 输出不仅是一种格式差异，更是将代码库输入 AI 系统进行分析、审查或其他任务的一种潜在更高效的方式。

#### Markdown 格式

要生成 Markdown 格式的输出，请使用 `--style markdown` 选项：

```bash
repomix --style markdown
```

Markdown 格式以层级方式组织内容：

````markdown
This file is a merged representation of the entire codebase, combining all repository files into a single document.

# File Summary

(Metadata and usage AI instructions)

# Repository Structure

```
src/
  cli/
    cliOutput.ts
    index.ts
```

(...remaining directories)

# Repository Files

## File: src/index.js

```
// File contents here
```

(...remaining files)

# Instruction

(Custom instructions from `output.instructionFilePath`)
````

该格式提供清晰易读的结构，既便于人类阅读，也易于 AI 系统解析。

#### JSON 格式

要生成 JSON 格式的输出，请使用 `--style json` 选项：

```bash
repomix --style json
```

JSON 格式以驼峰式命名的层级 JSON 对象组织内容：

```json
{
  "fileSummary": {
    "generationHeader": "This file is a merged representation of the entire codebase, combined into a single document by Repomix.",
    "purpose": "This file contains a packed representation of the entire repository's contents...",
    "fileFormat": "The content is organized as follows...",
    "usageGuidelines": "- This file should be treated as read-only...",
    "notes": "- Some files may have been excluded based on .gitignore, .ignore, and .repomixignore rules..."
  },
  "userProvidedHeader": "Custom header text if specified",
  "directoryStructure": "src/\n  cli/\n    cliOutput.ts\n    index.ts\n  config/\n    configLoader.ts",
  "files": {
    "src/index.js": "// File contents here",
    "src/utils.js": "// File contents here"
  },
  "instruction": "Custom instructions from instructionFilePath"
}
```

此格式非常适合：
- **程序化处理**：易于使用 JSON 库进行解析和操作
- **API 集成**：供 Web 服务和应用直接消费  
- **AI 工具兼容**：为机器学习和 AI 系统提供结构化格式
- **数据分析**：通过 `jq` 等工具轻松提取特定信息

##### 使用 `jq` 处理 JSON 输出

JSON 格式便于以编程方式提取特定信息：

```bash
# 列出所有文件路径
cat repomix-output.json | jq -r '.files | keys[]'

# 统计文件总数
cat repomix-output.json | jq '.files | keys | length'

# 提取特定文件内容
cat repomix-output.json | jq -r '.files["README.md"]'
cat repomix-output.json | jq -r '.files["src/index.js"]'

# 按扩展名查找文件
cat repomix-output.json | jq -r '.files | keys[] | select(endswith(".ts"))'

# 获取包含特定文本的文件
cat repomix-output.json | jq -r '.files | to_entries[] | select(.value | contains("function")) | .key'

# 提取目录结构
cat repomix-output.json | jq -r '.directoryStructure'

# 获取文件摘要信息
cat repomix-output.json | jq '.fileSummary.purpose'
cat repomix-output.json | jq -r '.fileSummary.generationHeader'

# 提取用户提供的头部（如果存在）
cat repomix-output.json | jq -r '.userProvidedHeader // "No header provided"'

# 创建带大小的文件列表
cat repomix-output.json | jq -r '.files | to_entries[] | "\(.key): \(.value | length) characters"'
```

要生成纯文本格式的输出，请使用 `--style plain` 选项：

### 远程仓库处理

Repomix 支持处理远程 Git 仓库，无需手动克隆。此功能允许你通过一条命令快速分析任意公开 Git 仓库。

要处理远程仓库，请使用 `--remote` 选项后跟仓库 URL：

```bash
repomix --remote https://github.com/yamadashy/repomix
```

你也可以使用 GitHub 的简写格式：

```bash
repomix --remote yamadashy/repomix
```

你可以指定分支名称、标签或提交哈希：

```bash
# 使用 --remote-branch 选项
repomix --remote https://github.com/yamadashy/repomix --remote-branch main

# 使用分支的 URL
repomix --remote https://github.com/yamadashy/repomix/tree/main
```

或使用特定的提交哈希：

```bash
# 使用 --remote-branch 选项
repomix --remote https://github.com/yamadashy/repomix --remote-branch 935b695

# 使用提交的 URL
repomix --remote https://github.com/yamadashy/repomix/commit/836abcd7335137228ad77feb28655d85712680f1
```

> [!NOTE]
> 出于安全考虑，默认不会加载远程仓库中的配置文件（`repomix.config.*`）。这能防止不受信任的仓库通过配置文件执行恶意代码。你的全局配置和 CLI 选项仍然会生效。若要信任远程仓库的配置，请使用 `--remote-trust-config` 或设置 `REPOMIX_REMOTE_TRUST_CONFIG=true`。
>
> 当将 `--config` 与 `--remote` 一起使用时，必须使用绝对路径（例如 `--config /home/user/repomix.config.json`）。

### 代码压缩

`--compress` 选项利用 [Tree-sitter](https://github.com/tree-sitter/tree-sitter) 执行智能代码提取，专注于保留关键的函数和类签名，同时移除实现细节。这有助于在保留重要结构信息的同时减少 Token 数量。

```bash
repomix --compress
```

例如，以下代码：

```typescript
import { ShoppingItem } from './shopping-item';

/**
 * Calculate the total price of shopping items
 */
const calculateTotal = (
  items: ShoppingItem[]
) => {
  let total = 0;
  for (const item of items) {
    total += item.price * item.quantity;
  }
  return total;
}

// Shopping item interface
interface Item {
  name: string;
  price: number;
  quantity: number;
}
```

将被压缩为：

```typescript
import { ShoppingItem } from './shopping-item';
⋮----
/**
 * Calculate the total price of shopping items
 */
const calculateTotal = (
  items: ShoppingItem[]
) => {
⋮----
// Shopping item interface
interface Item {
  name: string;
  price: number;
  quantity: number;
}
```

> [!NOTE]
> 这是一项实验性功能，我们将根据用户反馈和实际使用情况持续优化。

### Token 计数优化

了解代码库的 Token 分布对于优化 AI 交互至关重要。使用 `--token-count-tree` 选项可视化项目中的 Token 使用情况：

```bash
repomix --token-count-tree
```

这将显示带有 Token 计数的代码库层级视图：

```
🔢 Token Count Tree:
────────────────────
└── src/ (70,925 tokens)
    ├── cli/ (12,714 tokens)
    │   ├── actions/ (7,546 tokens)
    │   └── reporters/ (990 tokens)
    └── core/ (41,600 tokens)
        ├── file/ (10,098 tokens)
        └── output/ (5,808 tokens)
```

你还可以设置最小 Token 阈值以重点关注较大的文件：

```bash
repomix --token-count-tree 1000  # 仅显示 ≥1000 个 Token 的文件/目录
```

这有助于你：
- **识别占用大量 Token 的文件**，防止超出 AI 上下文限制
- **优化文件选择**，结合 `--include` 和 `--ignore` 模式  
- **规划压缩策略**，针对主要贡献者进行优化
- **平衡内容与上下文**，为 AI 分析做准备

### 大型代码库的输出分割

处理大型代码库时，打包输出可能会超出某些 AI 工具的文件大小限制（例如 Google AI Studio 的 1MB 限制）。使用 `--split-output` 自动将输出分割为多个文件：

```bash
repomix --split-output 1mb
```

这将生成编号文件，如：
- `repomix-output.1.xml`
- `repomix-output.2.xml`
- `repomix-output.3.xml`

大小可带单位指定：`500kb`、`1mb`、`2mb`、`1.5mb` 等。支持小数。

> [!NOTE]
> 文件按顶级目录分组以保持上下文连贯性。单个文件或目录绝不会跨多个输出文件分割。

```bash
repomix --mcp
```

#### 可用的 MCP 工具

以 MCP 服务器运行时，Repomix 提供以下工具：

1. **pack_codebase**：将本地代码目录打包为合并的 XML 文件供 AI 分析
  - 参数：
    - `directory`：要打包的目录绝对路径
    - `compress`：（可选，默认 false）启用 Tree-sitter 压缩以提取核心代码签名和结构，同时移除实现细节。在保留语义的同时减少约 70% 的 Token 使用量。通常不需要，因为 grep_repomix_output 允许增量内容检索。仅当你确实需要大型仓库的完整代码库内容时使用。
    - `includePatterns`：（可选）指定要包含的文件，使用 fast-glob 模式。多个模式可逗号分隔（例如 `"**/*.{js,ts}", "src/**,docs/**"`）。仅处理匹配文件。
    - `ignorePatterns`：（可选）指定额外排除的文件，使用 fast-glob 模式。多个模式可逗号分隔（例如 `"test/**,*.spec.js", "node_modules/**,dist/**"`）。这些模式补充 `.gitignore`、`.ignore` 和内置排除项。
    - `topFilesLength`：（可选，默认 10）在代码库分析指标摘要中显示的最大文件数量。

2. **attach_packed_output**：附加现有的 Repomix 打包输出文件供 AI 分析
  - 参数：
    - `path`：包含 repomix-output.xml 的目录路径或直接指向已打包仓库 XML 文件的路径
    - `topFilesLength`：（可选，默认 10）在指标摘要中显示的最大文件数量
  - 功能：
    - 接受包含 repomix-output.xml 文件的目录或直接指向 XML 文件的路径
    - 将文件注册到 MCP 服务器并返回与 pack_codebase 工具相同的结构
    - 提供对现有打包输出的安全访问，无需重新处理
    - 适用于使用之前生成的已打包仓库

3. **pack_remote_repository**：获取、克隆并打包 GitHub 仓库为合并的 XML 文件供 AI 分析
  - 参数：
    - `remote`：GitHub 仓库 URL 或 user/repo 格式（例如 `"yamadashy/repomix"`、`"https://github.com/user/repo"` 或 `"https://github.com/user/repo/tree/branch"`）
    - `compress`：（可选，默认 false）启用 Tree-sitter 压缩以提取核心代码签名和结构，同时移除实现细节。在保留语义的同时减少约 70% 的 Token 使用量。通常不需要，因为 grep_repomix_output 允许增量内容检索。仅当你确实需要大型仓库的完整代码库内容时使用。
    - `includePatterns`：（可选）指定要包含的文件，使用 fast-glob 模式。多个模式可逗号分隔（例如 `"**/*.{js,ts}", "src/**,docs/**"`）。仅处理匹配文件。
    - `ignorePatterns`：（可选）指定额外排除的文件，使用 fast-glob 模式。多个模式可逗号分隔（例如 `"test/**,*.spec.js", "node_modules/**,dist/**"`）。这些模式补充 `.gitignore`、`.ignore` 和内置排除项。
    - `topFilesLength`：（可选，默认 10）在代码库分析指标摘要中显示的最大文件数量。

4. **read_repomix_output**：读取 Repomix 生成的输出文件内容。支持通过行范围指定进行部分读取。
  - 参数：
    - `outputId`：要读取的 Repomix 输出文件 ID
    - `startLine`：（可选）起始行号（从 1 开始，包含）。若未指定则从头开始读取。
    - `endLine`：（可选）结束行号（从 1 开始，包含）。若未指定则读到末尾。
  - 功能：
    - 专为基于 Web 的环境或沙盒应用设计
    - 使用其 ID 检索之前生成的输出内容
    - 提供对打包代码库的安全访问，无需文件系统权限
    - 支持大文件的分块读取

5. **grep_repomix_output**：使用类似 grep 的功能和 JavaScript RegExp 语法在 Repomix 输出文件中搜索模式
  - 参数：
    - `outputId`：要搜索的 Repomix 输出文件 ID
    - `pattern`：搜索模式（JavaScript RegExp 正则表达式语法）
    - `contextLines`：（可选，默认 0）在每个匹配项前后显示的上下文行数。若指定了 beforeLines/afterLines 则被覆盖。
    - `beforeLines`：（可选）在每个匹配项前显示的上下文行数（类似 grep -B）。优先于 contextLines。
    - `afterLines`：（可选）在每个匹配项后显示的上下文行数（类似 grep -A）。优先于 contextLines。
    - `ignoreCase`：（可选，默认 false）执行不区分大小写的匹配
  - 功能：
    - 使用 JavaScript RegExp 语法实现强大的模式匹配
    - 支持上下文行以更好地理解匹配结果
    - 允许独立控制前后上下文行数
    - 提供大小写敏感和不敏感搜索选项

6. **file_system_read_file**：使用绝对路径从本地文件系统读取文件。包含内置安全验证以检测并防止访问包含敏感信息的文件。
  - 参数：
    - `path`：要读取的文件绝对路径
  - 安全功能：
    - 基于 [Secretlint](https://github.com/secretlint/secretlint) 实现安全验证
    - 阻止访问包含敏感信息（API 密钥、密码、机密）的文件
    - 验证绝对路径以防止目录遍历攻击

7. **file_system_read_directory**：使用绝对路径列出目录内容。返回格式化列表，清晰显示文件和子目录。
  - 参数：
    - `path`：要列出的目录绝对路径
  - 功能：
    - 清晰标识文件与目录（`[FILE]` 或 `[DIR]`）
    - 提供安全的目录遍历及完善的错误处理
    - 验证路径并确保其为绝对路径
    - 适用于探索项目结构及理解代码库组织方式

```text
# 安装命令插件（扩展功能）
/plugin install repomix-commands@repomix

# 安装仓库浏览器插件（AI 驱动的分析能力）
/plugin install repomix-explorer@repomix
```

**注意**：推荐将 `repomix-mcp` 作为基础插件。`repomix-commands` 提供便捷的斜杠命令，而 `repomix-explorer` 增加 AI 驱动的分析能力。虽然可以独立安装，但三者结合使用体验最佳。

或者，使用交互式插件安装器：

```text
/plugin
```

这将打开一个交互界面，你可以在其中浏览并安装可用插件。

#### 可用插件

**1. repomix-mcp**（MCP 服务器插件）

基础插件，通过 MCP 服务器集成提供 AI 驱动的代码库分析能力。

**功能：**
- 打包本地和远程仓库
- 搜索已打包的输出内容
- 读取文件并内置安全扫描（Secretlint）
- 自动 Tree-sitter 压缩（约减少 70% Token）

**2. repomix-commands**（斜杠命令插件）

提供便捷的斜杠命令以快速执行操作，支持自然语言。

**可用命令：**
- `/repomix-commands:pack-local` - 使用各种选项打包本地代码库
- `/repomix-commands:pack-remote` - 打包并分析远程 GitHub 仓库

**使用示例：**
```text
/repomix-commands:pack-local
Pack this project as markdown with compression

/repomix-commands:pack-remote yamadashy/repomix
Pack only TypeScript files from the yamadashy/repomix repository
```

**3. repomix-explorer**（AI 分析代理插件）

AI 驱动的仓库分析代理，利用 Repomix CLI 智能探索代码库。

**功能：**
- 自然语言代码库探索与分析
- 智能模式发现与代码结构理解
- 使用 grep 和定向文件读取进行增量分析
- 自动管理大型仓库的上下文

**可用命令：**
- `/repomix-explorer:explore-local` - 在 AI 协助下分析本地代码库
- `/repomix-explorer:explore-remote` - 在 AI 协助下分析远程 GitHub 仓库

**使用示例：**
```text
/repomix-explorer:explore-local ./src
Find all authentication-related code

/repomix-explorer:explore-remote facebook/react
Show me the main component architecture
```

该代理自动：
1. 运行 `npx repomix@latest` 打包仓库
2. 使用 Grep 和 Read 工具高效搜索输出内容
3. 提供全面分析而不消耗过多上下文

#### 优势

- **无缝集成**：Claude 可直接分析代码库，无需手动准备
- **自然语言**：使用对话式命令替代记忆 CLI 语法
- **始终最新**：自动调用 `npx repomix@latest` 获取最新功能
- **内置安全**：自动 Secretlint 扫描防止敏感数据泄露
- **Token 优化**：针对大型代码库的 Tree-sitter 压缩

更多详情请参阅 `.claude/plugins/` 目录中的插件文档。

### Agent Skills 生成

Repomix 可生成 [Claude Agent Skills](https://docs.anthropic.com/en/docs/claude-code/skills) 格式输出，创建结构化的 Skills 目录作为 AI 助手的可重用代码库参考。当你希望引用远程仓库中的实现时，此功能尤为强大。

#### 基础用法

```bash
# 从本地目录生成 Skills
repomix --skill-generate

# 自定义 Skills 名称
repomix --skill-generate my-project-reference

# 从远程仓库生成
repomix --remote https://github.com/user/repo --skill-generate
```

运行命令后，Repomix 会提示你选择保存 Skills 的位置：

1. **个人 Skills**（`~/.claude/skills/`）- 在你的所有项目中可用
2. **项目 Skills**（`.claude/skills/`）- 可通过 git 与团队共享

#### 非交互式用法

对于 CI 流水线及自动化脚本，可使用 `--skill-output` 和 `--force` 跳过所有交互提示：

```bash
# 直接指定输出目录
repomix --skill-generate --skill-output ./my-skills

# 使用 --force 跳过覆盖确认
repomix --skill-generate --skill-output ./my-skills --force

# 完整非交互式示例
repomix --remote user/repo --skill-generate my-skill --skill-output ./output --force
```

#### 生成的结构

Skill 将按以下结构生成：

```text
.claude/skills/<skill-name>/
├── SKILL.md                 # 主 Skills 元数据与文档
└── references/
    ├── summary.md           # 用途、格式及统计信息
    ├── project-structure.md # 带行数统计的目录树
    ├── files.md             # 所有文件内容（grep 友好）
    └── tech-stacks.md       # 语言、框架与依赖项
```

#### 包含内容

- **SKILL.md**：包含 Skills 元数据、文件/行/Tokken 计数、概览及使用说明
- **summary.md**：解释 Skills 目的、使用指南，并提供按文件类型和语言划分的统计信息
- **project-structure.md**：带每文件行数统计的目录树，便于快速定位文件
- **files.md**：所有文件内容（带语法高亮头），针对 grep 友好搜索优化
- **tech-stacks.md**：从依赖文件自动检测的各包技术栈（`package.json`、`requirements.txt`、`Cargo.toml` 等）

#### 自动生成 Skills 名称

若未提供名称，Repomix 将自动生成：

```bash
repomix src/ --skill-generate                # → repomix-reference-src
repomix --remote user/repo --skill-generate  # → repomix-reference-repo
repomix --skill-generate CustomName          # → custom-name (标准化为短横线格式)
```

#### 与 Repomix 功能集成

Skill 生成遵循所有标准 Repomix 选项：

```bash
# 带文件过滤生成 Skills
repomix --skill-generate --include "src/**/*.ts" --ignore "**/*.test.ts"

# 带压缩生成 Skills
repomix --skill-generate --compress

# 从远程仓库生成 Skills
repomix --remote yamadashy/repomix --skill-generate
```

## ⚙️ 配置

Repomix 支持多种配置文件格式，兼顾灵活性与易用性。

### 配置文件格式

Repomix 将按以下优先级自动搜索配置文件：

1. **TypeScript**（`repomix.config.ts`、`repomix.config.mts`、`repomix.config.cts`）
2. **JavaScript/ES Module**（`repomix.config.js`、`repomix.config.mjs`、`repomix.config.cjs`）
3. **JSON**（`repomix.config.json5`、`repomix.config.jsonc`、`repomix.config.json`）

#### JSON 配置

在项目根目录创建 `repomix.config.json` 文件：

```bash
repomix --init
```

这将创建一个带有默认设置的 `repomix.config.json` 文件。

#### TypeScript 配置

TypeScript 配置文件提供最佳的开发者体验，支持完整的类型检查和 IDE 支持。

**安装：**

若要将 TypeScript 或 JavaScript 配置与 `defineConfig` 配合使用，需将 Repomix 作为开发依赖安装：

```bash
npm install -D repomix
```

**示例：**

```typescript
// repomix.config.ts
import { defineConfig } from 'repomix';

export default defineConfig({
  output: {
    filePath: 'output.xml',
    style: 'xml',
    removeComments: true,
  },
  ignore: {
    customPatterns: ['**/node_modules/**', '**/dist/**'],
  },
});
```

**优势：**
- ✅ IDE 中完整的 TypeScript 类型检查
- ✅ 优秀的 IDE 自动补全与 IntelliSense
- ✅ 使用动态值（时间戳、环境变量等）

**动态值示例：**

```typescript
// repomix.config.ts
import { defineConfig } from 'repomix';

// 生成基于时间戳的文件名
const timestamp = new Date().toISOString().slice(0, 19).replace(/[:.]/g, '-');

export default defineConfig({
  output: {
    filePath: `output-${timestamp}.xml`,
    style: 'xml',
  },
});
```

#### JavaScript 配置

JavaScript 配置文件与 TypeScript 工作方式相同，同样支持 `defineConfig` 和动态值。

### 包含与排除

#### 包含模式

Repomix 现在支持使用 [glob 模式](https://github.com/mrmlnc/fast-glob?tab=readme-ov-file#pattern-syntax) 指定要包含的文件。这允许更灵活强大的文件选择：

- 使用 `**/*.js` 包含任意目录下的所有 JavaScript 文件
- 使用 `src/**/*` 包含 `src` 目录及其子目录中的所有文件
- 组合多个模式如 `["src/**/*.js", "**/*.md"]` 以同时包含 `src` 中的 JS 文件和所有 Markdown 文件

#### 排除模式

Repomix 提供多种设置忽略模式的方法，用于在打包过程中排除特定文件或目录：

- **.gitignore**：默认情况下，会使用项目 `.gitignore` 文件和 `.git/info/exclude` 中列出的模式。此行为可通过 `ignore.useGitignore` 配置或 `--no-gitignore` CLI 选项控制。
- **.ignore**：你可以在项目根目录使用 `.ignore` 文件，格式与 `.gitignore` 相同。该文件被 ripgrep 和 silver searcher 等工具所支持，可减少维护多个忽略文件的需要。此行为可通过 `ignore.useDotIgnore` 配置或 `--no-dot-ignore` CLI 选项控制。
- **默认模式**：Repomix 内置了常用排除文件和目录的默认列表（如 node_modules、.git、二进制文件等）。此功能可通过 `ignore.useDefaultPatterns` 配置或 `--no-default-patterns` CLI 选项控制。详情请见 [defaultIgnore.ts](src/config/defaultIgnore.ts)。
- **.repomixignore**：你可以在项目根目录创建 `.repomixignore` 文件以定义 Repomix 专属的忽略模式。该文件格式与 `.gitignore` 相同。
- **自定义模式**：可通过配置文件中的 `ignore.customPatterns` 选项指定额外的忽略模式。你也可通过 `-i, --ignore` CLI 选项覆盖此设置。

**优先级顺序（从高到低）：**

1. 自定义模式 (`ignore.customPatterns`)
2. 忽略文件 (`.repomixignore`, `.ignore`, `.gitignore` 和 `.git/info/exclude`)：嵌套目录中，更深层的文件优先级更高；同目录下按任意顺序合并。
3. 默认模式（当 `ignore.useDefaultPatterns` 为 true 且未使用 `--no-default-patterns` 时）

此方法允许根据项目需求灵活配置文件排除。它通过确保排除安全敏感文件和大型二进制文件，同时防止机密信息泄露，帮助优化生成的打包文件大小。

注意：默认情况下，二进制文件不会包含在打包输出中，但其路径会列出在输出的“仓库结构”部分。这提供了完整的仓库结构概览，同时保持打包文件高效且基于文本。

### 自定义指令

`output.instructionFilePath` 选项允许你指定一个包含项目详细说明或上下文的独立文件。这让 AI 系统能够理解项目的特定上下文和需求，从而可能带来更相关、更具针对性的分析或建议。

使用此功能的方法示例：

1. 在项目根目录创建名为 `repomix-instruction.md` 的文件：

```markdown
# Coding Guidelines

- Follow the Airbnb JavaScript Style Guide
- Suggest splitting files into smaller, focused units when appropriate
- Add comments for non-obvious logic. Keep all text in English
- All new features should have corresponding unit tests

# Generate Comprehensive Output

- Include all content without abbreviation, unless specified otherwise
- Optimize for handling large codebases while maintaining output quality
```

2. 在 `repomix.config.json` 中添加 `instructionFilePath` 选项：

```json5
{
  "output": {
    "instructionFilePath": "repomix-instruction.md",
    // other options...
  }
}
```

当 Repomix 生成输出时，它将在专用部分包含 `repomix-instruction.md` 的内容。

注意：指令内容追加到输出文件末尾。此位置对 AI 系统特别有效。Anthropic 在其文档中提供了相关见解：  
https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/long-context-tips

> Put long-form data at the top: Place your long documents and inputs (~20K+ tokens) near the top of your prompt, above
> your query, instructions, and examples. This can significantly improve Claude's performance across all models.
> Queries at the end can improve response quality by up to 30% in tests, especially with complex, multi-document inputs.

### 注释移除

当 `output.removeComments` 设置为 `true` 时，Repomix 会尝试从支持的文件类型中移除注释。此功能有助于减小输出文件大小并聚焦于核心代码内容。

支持的语言包括：  
HTML、CSS、JavaScript、TypeScript、Vue、Svelte、Python、PHP、Ruby、C、C#、Java、Go、Rust、Swift、Kotlin、Dart、Shell 和 YAML。

注意：注释移除过程采用保守策略以避免误删代码。在复杂情况下，部分注释可能会被保留。

## 🔍 安全检查

Repomix 内置了使用 [Secretlint](https://github.com/secretlint/secretlint) 检测文件中潜在敏感信息的安全检查功能。此功能帮助你在分享打包仓库前识别可能的安全风险。

安全检查结果将在 CLI 输出中显示在打包过程完成后。如果检测到可疑文件，你将看到这些文件的列表及警告消息。

示例输出：

```
🔍 Security Check:
──────────────────
2 suspicious file(s) detected:
1. src/utils/test.txt
2. tests/utils/secretLintUtils.test.ts

Please review these files for potentially sensitive information.
```

默认情况下，Repomix 的安全检查功能已启用。你可通过在配置文件中将 `security.enableSecurityCheck` 设置为 `false` 来禁用它：

```json
{
  "security": {
    "enableSecurityCheck": false
  }
}
```

或使用 `--no-security-check` CLI 选项：

```bash
repomix --no-security-check
```

> [!NOTE]
> 禁用安全检查可能会暴露敏感信息。请谨慎使用此选项，仅在必要时（如处理包含示例凭据的测试文件或文档时）使用。

## 🤖 配合 GitHub Actions 使用

你也可以在 GitHub Actions 工作流中使用 Repomix。这非常适合自动化打包代码库以供 AI 分析。

基础用法：

```yaml
- name: Pack repository with Repomix
  uses: yamadashy/repomix/.github/actions/repomix@main
  with:
    output: repomix-output.xml
    style: xml
```

使用 `--style` 生成不同格式的输出：

```yaml
- name: Pack repository with Repomix
  uses: yamadashy/repomix/.github/actions/repomix@main
  with:
    output: repomix-output.md
    style: markdown
```

```yaml
- name: Pack repository with Repomix (JSON format)
  uses: yamadashy/repomix/.github/actions/repomix@main
  with:
    output: repomix-output.json
    style: json
```

压缩特定目录并打包：

```yaml
- name: Pack repository with Repomix
  uses: yamadashy/repomix/.github/actions/repomix@main
  with:
    directories: src tests
    include: "**/*.ts,**/*.md"
    ignore: "**/*.test.ts"
    output: repomix-output.txt
    compress: true
```

将输出文件作为 Artifact 上传：

```yaml
- name: Pack repository with Repomix
  uses: yamadashy/repomix/.github/actions/repomix@main
  with:
    directories: src
    output: repomix-output.txt
    compress: true

- name: Upload Repomix output
  uses: actions/upload-artifact@v4
  with:
    name: repomix-output
    path: repomix-output.txt
```

完整工作流示例：

```yaml
name: Pack repository with Repomix

on:
  workflow_dispatch:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  pack-repo:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Pack repository with Repomix
        uses: yamadashy/repomix/.github/actions/repomix@main
        with:
          output: repomix-output.xml

      - name: Upload Repomix output
        uses: actions/upload-artifact@v4
        with:
          name: repomix-output.xml
          path: repomix-output.xml
          retention-days: 30
```

查看完整工作流示例 [在此处](https://github.com/yamadashy/repomix/blob/main/.github/workflows/pack-repository.yml)。

### Action 输入参数

| Name | Description | Default |
|------|-------------|---------|
| `directories` | 要处理的目录列表（空格分隔，例如 `src tests docs`） | `.` |
| `include` | 包含文件的逗号分隔 glob 模式（例如 `**/*.ts,**/*.md`） | `""` |
| `ignore` | 忽略文件的逗号分隔 glob 模式（例如 `**/*.test.ts,**/node_modules/**`） | `""` |
| `output` | 打包文件的相对路径（扩展名决定格式：`.txt`、`.md`、`.xml`） | `repomix-output.xml` |
| `compress` | 启用智能压缩以修剪实现细节并减小输出体积 | `true` |
| `style` | 输出样式（`xml`、`markdown`、`json`、`plain`） | `xml` |
| `additional-args` | repomix CLI 的额外原始参数（例如 `--no-file-summary --no-security-check`） | `""` |
| `repomix-version` | 要安装的 npm 包版本（支持 semver 范围、标签或特定版本如 `0.2.25`） | `latest` |

### Action 输出参数

| Name | Description |
|------|-------------|
| `output_file` | 生成的输出文件路径。可在后续步骤中用于 Artifact 上传、LLM 处理或其他操作。该文件包含基于指定选项格式化的代码库表示。 |

## 📚 作为库使用

除了将 Repomix 用作 CLI 工具外，你还可以在 Node.js 应用中将其作为库调用。

### 安装

```bash
npm install repomix
```

### 基础用法

```javascript
import { runCli, type CliOptions } from 'repomix';

// 使用自定义选项处理当前目录
async function packProject() {
  const options = {
    output: 'output.xml',
    style: 'xml',
    compress: true,
    quiet: true
  } as CliOptions;
  
  const result = await runCli(['.'], process.cwd(), options);
  return result.packResult;
}
```

### 处理远程仓库

```javascript
import { runCli, type CliOptions } from 'repomix';

// 克隆并处理 GitHub 仓库
async function processRemoteRepo(repoUrl) {
  const options = {
    remote: repoUrl,
    output: 'output.xml',
    compress: true
  } as CliOptions;
  
  return await runCli(['.'], process.cwd(), options);
}
```

### 使用核心组件

如需更多控制权，可使用底层 API：

```javascript
import { searchFiles, collectFiles, processFiles, TokenCounter } from 'repomix';

async function analyzeFiles(directory) {
  // 查找并收集文件
  const { filePaths } = await searchFiles(directory, { /* config */ });
  const rawFiles = await collectFiles(filePaths, directory);
  const processedFiles = await processFiles(rawFiles, { /* config */ });
  
  // 统计 Token
  const tokenCounter = new TokenCounter('o200k_base');
  
  // 返回分析结果
  return processedFiles.map(file => ({
    path: file.path,
    tokens: tokenCounter.countTokens(file.content)
  }));
}
```

更多示例可参考 [website/server/src/remoteRepo.ts](https://github.com/yamadashy/repomix/blob/main/website/server/src/remoteRepo.ts) 源码，其中展示了 repomix.com 如何使用该库。

### 打包（Bundling）

使用 Rolldown 或 esbuild 等工具捆绑 repomix 时，部分依赖必须保持外部引入，且需复制 WASM 文件：

**外部依赖（不可捆绑）：**
- `tinypool` - 通过文件路径启动工作线程

**需复制的 WASM 文件：**
- `web-tree-sitter.wasm` → 与打包后的 JS 同目录（代码压缩功能必需）
- Tree-sitter 语言文件 → 由 `REPOMIX_WASM_DIR` 环境变量指定的目录

完整示例见 [website/server/scripts/bundle.mjs](https://github.com/yamadashy/repomix/blob/main/website/server/scripts/bundle.mjs)。
