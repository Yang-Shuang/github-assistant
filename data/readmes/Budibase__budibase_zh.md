## ✨ 核心特性

### 在一个平台上运行你的所有运营工作

处理请求、自动化工作流程、管理业务流程，并连接你的业务系统——无需拼接多个工具。

员工每天提出问题、申请审批和报告问题。Budibase Agent 能够理解这些需求并自动完成相关操作。

<br /><br />

### 团队可借助 AI Agent 执行的运营任务

员工每天提出问题、申请审批和报告问题。Budibase Agent 能够理解这些需求并自动完成相关操作。

<p align="center">
  <img alt="Budibase chat deploy" src="https://res.cloudinary.com/daog6scxm/image/upload/v1775573887/github/Agent_Chat.jpg">
</p>

<br /><br />

### 能够执行操作的 Agent

Budibase Agent 不仅能回答问题，还能在你的业务中运行工作流——自动创建记录、路由审批、更新应用并通知团队。

<p align="center">
  <img alt="Budibase agent actions" src="https://res.cloudinary.com/daog6scxm/image/upload/v1775572270/github/Agent_Actions.jpg">
</p>
<br /><br />

### 连接你的业务工具链

集成数据库、AI 模型和业务应用，使 Agent 和自动化流程能够在整个运营中采取行动。

### 安全自信地部署

Budibase 是开源的，且具备出色的可扩展性。使用 Budibase，你可以在自有基础设施上自行托管，并全局管理用户、入职流程、SMTP、应用、群组、主题等。你还可以为用户/群组提供门户，并将用户管理权限下放给群主。

## Budibase 公开 API

正如我们在 Budibase 中构建的其他功能一样，我们的公开 API（API）简单易用、灵活，并引入了新的扩展性。简而言之，Budibase API 支持：

- 将 Budibase 作为后端使用
- 跨系统互操作性

#### 文档

你可以在以下位置了解更多关于 Budibase API 的信息：

- [通用文档](https://docs.budibase.com/docs/public-api)：了解如何获取 API Key、如何使用 OpenAPI Spec 以及如何在 Postman 中使用它

### 仓库结构说明

Budibase 是一个由 Lerna 管理的 Monorepo（单体仓库）。Lerna 负责构建和发布 Budibase 的各个包。从宏观角度来看，构成 Budibase 的包如下：

- [packages/builder](https://github.com/Budibase/budibase/tree/HEAD/packages/builder) - 包含 Budibase Builder 客户端 Svelte 应用的代码。
- [packages/client](https://github.com/Budibase/budibase/tree/HEAD/packages/client) - 在浏览器中运行的模块，负责读取 JSON 定义并从中生成动态的 Web 应用。
- [packages/server](https://github.com/Budibase/budibase/tree/HEAD/packages/server) - Budibase 服务端。该 Koa 应用负责为 Builder 和 Budibase 应用提供前端 JS，并提供与数据库及文件系统交互的 API。

更多信息请参阅 [CONTRIBUTING.md](https://github.com/Budibase/budibase/blob/HEAD/docs/CONTRIBUTING.md)
